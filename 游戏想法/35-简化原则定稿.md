## 二、商品怎么到玩家手里（定稿）

### ❌ 不采用的模型（写进旧文档时可标「已废弃」）

```
买家 → 商家出餐 → 骑手取件 → 运送 → 送达确认 → 背包
         ↑ 子单        ↑ 区域匹配   ↑ ETA   ↑ 馆驿卒托底
```

中间环节：**骑手、快递员、跑腿、配送子单、运费、送达状态** —— **v1.0 起不单独做**。

### ✅ 采用的模型（默认）

```
买家点 offer → 扣点托管 → 卖家(NPC)履约 → 通知 → 物进背包
```

| 步骤 | 四象 | 玩家看见 |
|------|------|----------|
| 1 | 事 `order` | 陈师傅菜单里点「标准汤面 · 15 点」 |
| 2 | 事 `ledger` | 余额 300 → 285 |
| 3 | 事 `message` | 通知：「标准汤面好了」 |
| 4 | 物 `stack` | 背包 +1 一碗面 |

**没有：** 快递员、骑手、取件、在路上、运费、门牌地址。

### 和「取餐」按钮的关系

v1.0 实现里保留 **一次点击「确认收进背包」**（API：`pickup`），语义是 **确认收货**，不是「本人走到食堂窗口」。

文案统一用：**确认收货 / 收进背包**，不用「取餐」「配送」「送达」。

## 三、其它领域的同样简化

| 领域 | 不绕弯 | 暂不做 |
|------|--------|--------|
| **通讯** | 系统通知列表（像邮箱） | 玩家私信、聊天室 |
| **地址** | 只认「市 + handle」 | 省市区门牌、GPS |
| **钱** | 只有「点」 | 多币种、提现、灯油/银币别名 |
| **开店** | 以后再说 | v1.0 不做店铺实体 |
| **履约** | NPC 即时出餐 | 厨师排班、库存扣料（v1.0 可省略） |
| **托底** | 余额不足就提示 | 馆驿卒、超时派单 |

## 四、文档写法约定

1. **新功能先问**：能不能放进「下单 → 通知 → 背包」或「打卡 → 通知」？不能就后置。  
2. **旧文档**里出现骑手、配送、子单、ETA、馆驿卒 —— 标 **「v1.0 不做 / 已简化」**，不要当现行规范。  
3. **版本路线图**不再把「配送」单列为 v1.3 大里程碑；若以后要「送到家」，优先做成 **加运费的一键直收**，不恢复骑手链。  
4. **NPC 吴跑腿** 等角色：仅 lore 露面，**不预告配送玩法**。

## 五、与四象的对应

| 象 | v1.0 最小闭环 |
|----|----------------|
| 人 | player + 配置 NPC |
