# 平台职业图谱：简化世界的分工

> 状态：**职业一览（与简化原则对齐）**  
> 记录时间：2026-09-13（修订）  
> 上位约束：[35-简化原则定稿](./35-简化原则定稿.md) · [32-四象统一定稿](./32-四象统一定稿.md)  
> 说明：同一玩家可兼多职；**硬边界由系统资质控制**。幻想/科幻称呼只换皮，**不增加物流环节**。

---

## 一、一句话

米拉世界里，职业不是「模拟现实工种大全」，而是 **谁挂 offer、谁下单、谁读通知、谁打卡**。

**商品路径定稿：** 买家点 offer → 扣点 → 通知 → 收进背包。  
**没有：** 骑手、快递员、取件、在路上、运费、配送子单。

> 旧版「有人做菜、有人跑腿」的描述已过时；跑腿类职业 **玩法层面取消**，见 §四。

---

## 二、判断标准（留 / 删 / 新生）

| 留 | 删或后置 |
|----|----------|
| 对应四象：人挂 offer、地 visit、事 order/message、物 stack | 专门「把货从 A 运到 B」 |
| 异步、离线可完成 | 实时走位、子单接力、区域派单 |
| 一口价 + 一条 ledger 能说清 | 运费、ETA、馆驿卒托底 |

---

## 三、v1.0 必留（当前能玩或已露面）

| 称呼 | 四象 | 平台上做什么 | 举例 |
|------|------|--------------|------|
| **食客 / 消费者** | 事 `order` | 点 NPC offer，扣点，收进背包 | 陈师傅 · 标准汤面 15 点 |
| **旅人 / 探索者** | 事 `visit` | 打卡市、逛 spot | 第一次到晚霞岸 |
| **通知读者** | 事 `message` | 读系统/NPC 通知（人人默认） | 「标准汤面好了」 |
| **卖家（NPC）** | 人 + 物 `offer` | 挂菜单、履约；**人即店** | 陈师傅 |
| **配置型 NPC** | 人 + lore | 指方向、写世界观，无独立玩法 | 小林、吴跑腿（仅露面） |

**v1.0 不收录为玩法职业：** 骑手、快递员、信使、店主（玩家）、律师、说书人（留痕）。

## 四、玩法层面取消或后置（旧文档常见，勿再当规范）

| 旧职业 | 原设想 | 简化后 |
|--------|--------|--------|
| **骑手 / 快递员** | 出餐后配送 | **取消**；物直收背包 |
| **行者 / 信使 / 信鸦使** | 跑腿取送 | **取消**；合并进 order 完成 |
| **吴跑腿（玩法）** | 接驳、配送 | **仅 lore** |
| **馆驿卒 / 托底派单** | 无人接单系统补位 | **不做**；余额不足即失败 |
| **商品单 B₂ 配送环节** | 商家 + 骑手拆单 | **合并**为 seller 一口价 offer |
| **服务员（上门/位移）** | 人到场履约 | **后置**；若做则改为异步交作业，非外卖 |
| **保镖（护送类）** | 依附「在路上」 | **后置** |
| **运费 / ETA / 区域派单** | 配送链配套 | **取消**独立版本（见 `34`） |

**世界观里可以还有「跑腿」故事；平台上不给他们单独按钮和分账。**

## 五、简化后会变清晰的新角色（重点）

简化不是只删人，而是 **把原来散在多人手里的活收成少数几种**：

| 新角色（称呼可换皮） | 做什么 | 版本 |
|----------------------|--------|------|
| **卖家 Seller** | 挂 `offer`；买家直收，无第三环节 | v1.0 NPC · v1.2 玩家 |
| **Offer 设计师** | 配物品 + 价 + 文案；不写物流 | v1.0 配置 · v1.2 玩家 |
| **通知写手** | 写 message 模板、订单里程碑语气 | v1.1 |
| **逛点 / spot 作者** | 打卡彩蛋、首次到访文案 | v1.1 |
| **账房 / 审计** | ledger 异议、分账核对 | v2 争议 |
| **异步委托发布者** | 「我要」发 bounty，交付仍走通知+物 | v1.5 |

**核心合并：** 旧「店主 + 厨师 + 骑手」→ **一个 seller actor + 一条 order**。

## 六、按版本可扩展（仍遵守 35）

### v1.1 — 烟火

| 称呼 | 做什么 |
|------|--------|
| 通知写手、逛点作者、NPC 对白作者 | 只加字，不加系统 |

仍不做：玩家挂单、私信、配送。

### v1.2 — 开灶

| 称呼 | 做什么 |
|------|--------|
| **玩家卖家** | 自己挂 offer；**店 = 人** |
| **作坊 / 菜单设计** | 多 offer、简单 recipe |

买家路径不变：点 → 通知 → 背包。

### v1.4 — 当班

| 称呼 | 做什么 |
|------|--------|
| **卖家 auto** | 离线代接单/履约（日志 message） |

是 **卖家自己的日程**，不是雇骑手。

### v1.5 — 我要

| 称呼 | 做什么 |
|------|--------|
| **发单者** | bounty record |
| **接单人** | 异步交付，走 message + stack/ledger |

### v2.0+ — 社会 / 创作

| 称呼 | 做什么 |
|------|--------|
| **说书人 / 计史官** | trace 留痕 |
| **律师 / 仲裁 / 馆吏** | dispute、馆规 |
| **编剧 / 方案师 / Studio** | Blueprint、数字 offer（v3） |

准入：必须先落四象（`32`），且 **不恢复配送链**。

## 十三、职业从哪来？

```
四象（人·地·事·物）+ credits
    + 简化原则（无中间物流）
    + 异步（通知 = 邮箱）
    + 潮灯/科幻/玄幻皮肤
    ────────────────────────
    = 上表「能干活的名字」
```

| 原则 | 说明 |
|------|------|
| **先有用，再有皮** | 每个职业对应 offer / visit / message / ledger |
| **可兼职** | 中午食客、v1.2 晚上卖家 |
| **要资质才碰权** | 律师、发单等后置 |
| **幻想不增环节** | 换称呼不能加骑手 |

## 十五、小结

简化世界里，**能留下的职业** = 直接参与 **探索、点单、读通知、挂 offer、写文案、管账** 的人。  
**会消失的是玩法职业** = 一切「中间运货」角色。  
**会诞生的是合并后的角色** = **卖家、Offer 设计师、通知写手、逛点作者**。

> 同一双手可以打卡、点面、读通知；v1.2 起还可以挂一碗面。  
> 职业不是等级表上的格子，是你今天选择怎么参与潮灯市——**且不必雇一个快递员。**
