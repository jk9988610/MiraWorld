# 现代地址体系定稿

> 状态：**世界观最终方向**  
> 记录时间：2026-09-13（修订：去掉省；五段式统一地址）  
> 定夺：**只收录能统一的**；固定 **市·区·街道·小区·户号** 五段；货币仍 **credits / 点**（`30`）

---

## 一、原则：能统一的才收录

| 做 | 不做 |
|----|------|
| 全球同一套 **五段地址** | ❌ 省 / 国（各地不好统一，**不收录**） |
| 城市代号 **A市、B市、C市** | ❌ 奇幻地名、无法落进五段的地点 |
| 区名像真区：**枢纽区、滨湖区** | ❌ 字母当区名（不叫「A区」） |
| 户号 **单元+门牌合一** | ❌ 单元、门牌拆两个字段（易乱） |

**口诀：五段到底；户号用横杠；对不上的不进门。**

---

## 二、统一五段（全服唯一标准）

| 段 | 字段 | 必填 | 示例 |
|----|------|------|------|
| 1 市 | `city` | ✅ | `A市` |
| 2 区 | `district` | ✅ | `枢纽区` |
| 3 街道 | `street` | 店铺/家园要 | `中心街道` |
| 4 小区 | `community` | 店铺/家园要 | `接驳小区` |
| 5 户号 | `room` | 家园/配送要 | `3-502` |

### 2.1 户号（比「单元+门牌」更简单）

**一段写完：** `{单元}-{门牌}`

| 写法 | 含义 |
|------|------|
| `3-502` | 3 单元 502 室 |
| `1-0` | 1 单元底商（食堂等点位可挂） |
| （空） | 只到小区：地图打卡、纯区节点 |

不用两个字段，不用写「单元」「号」字样——**显示时**可加：`3单元502` 由程序从 `3-502` 格式化。

### 2.2 三种显示长度（够用）

| 级别 | 用在哪 | 示例 |
|------|--------|------|
| **短** | 地图、NPC 常住 | `A市 · 枢纽区` |
| **中** | 店铺、食堂 | `A市 枢纽区 中心街道 接驳小区` |
| **全** | 家园、配送单 | `A市 枢纽区 中心街道 接驳小区 3-502` |

### 2.3 技术表示（二选一，推荐 ①）

**① 五字段对象（推荐）**

```json
{
  "city": "A市",
  "district": "枢纽区",
  "street": "中心街道",
  "community": "接驳小区",
  "room": "3-502"
}
```

**② 单字符串路径（日志、URL）**

```
A市/枢纽区/中心街道/接驳小区/3-502
```

缺段就省略末尾：`A市/枢纽区`（地图节点）

```python
def format_address(a, level="short"):
    if level == "short":
        return f"{a['city']} · {a['district']}"
    parts = [a["city"], a["district"], a.get("street"), a.get("community"), a.get("room")]
    return " ".join(p for p in parts if p)
```

## 六、不收录什么

以下 **不进地点库 / 地址表**：

- 省、国、州、realm
- 无法写成五段的奇幻场景
- 玩家随口起的、未审核通过的地名（v2 以前）

玩法上的「势力」「阵营」若不能落五段，用 **标签** 挂在用户或店铺上，**不当地址**。
