# 地址与世界观定稿（两段式）

> 状态：**世界观 + 地址最终方向**  
> 记录时间：2026-09-13（修订：只保留 **市 · 区**）  
> 原则：**宏观表述，能简化就简化**；对不上的 **不收录**；货币仍 **credits / 点**（`30`）

---

## 一、定夺

| 项 | 选择 |
|----|------|
| **地址** | 只有两段：**市 · 区** |
| **不要** | 省、街道、小区、户号、格 K14、交叉点…… |
| **城市** | 可用代号或专名，如 **潮灯市**、**A市** |
| **区** | 真区名风格，如 **晚霞区**、枢纽区 |
| **玩法** | 探索 · 点菜 · 通知（`29`） |

**口诀：说到哪儿，就到 **市、区**；别往下细了。**

---

## 二、唯一标准地址

### 2.1 两段

| 段 | 字段 | 必填 | 示例 |
|----|------|------|------|
| 市 | `city` | ✅ | `潮灯市` |
| 区 | `district` | ✅ | `晚霞区` |

**显示：** `潮灯市 · 晚霞区`  
**路径（API/日志）：** `潮灯市/晚霞区`

```json
{ "city": "潮灯市", "district": "晚霞区" }
```

### 2.2 够用在哪

| 场景 | 地址 | 说明 |
|------|------|------|
| 地图打卡 | 潮灯市 · 晚霞区 | 来过即染色 |
| NPC 常住 | 潮灯市 · 枢纽区 | 写到区即可 |
| 系统食堂 | 潮灯市 · 枢纽区 | 店挂在区内，不另写门牌 |
| 玩家「我在哪」 | 当前市 + 当前区 | 宏观足够 |
| 配送（v1.3） | 仍只到 **区** | 异步文案：「送到晚霞区」；不假装精确到门 |
| 家园（若有） | 锚定在某 **区** | 区内摆放是玩法层，不是地址段 |

### 2.3 刻意不做的细度

以下 **不进地址表**（需要的话用玩法字段，不拼进住址）：

- 街道、小区、单元、门牌  
- 格号 K14、坐标、交叉点  
- 省、国  

> 一切都是宏观表述：**你知道在晚霞区就够了。**
