# 点菜式成长：玩家自己在乎自己要什么

> 状态：核心玩法构思  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、一句话

**系统不再给玩家派单，也没有主线。** 系统不在乎你怎么成长——**你自己得在乎**。  
你想吃什么、什么口味，你在「菜单」上点清楚；**厨师**（人、势力、或你雇来的创作者）按单做菜；**厨房与收银**由系统维持，但不替你决定人生。  
系统若提供偏新手、偏简单的单，也只挂在**悬赏栏 / 公告栏**上，谁爱接谁接；**订阅前不做任何推送**，全靠自己探索。

---

## 二、为什么要反对「系统派单」

| 传统 MMO / 任务板 | 问题 |
|-------------------|------|
| 系统发日常、发主线、发活动、弹窗催单 | 玩家变成**接单机器** |
| 奖励由策划写死 | 成长路径人人相同，**与「我」无关** |
| 系统假装在乎你 | 实则只在乎在线时长与消耗 |

本作立场：

> **系统是中立的馆子和规则，不是关心你的导师。**  
> 没有「为你好」的任务列表；只有「你自己点的单」。

这不是反任务，是反 **被派发的、与自我无关的任务**。

## 三、菜馆隐喻（完整映射）

| 菜馆 | 游戏世界 |
|------|----------|
| **食客（你）** | 玩家 — 知道自己想吃什么，或愿意尝新 |
| **菜单** | **成长菜单 / 委托单模板** — 你勾选目标、口味、预算 |
| **口味** | 玩法倾向：调查 / 战斗 / 社交 / 收集 / 叙事 / 经营… |
| **点菜行为** | 玩家主动创建 **「我要」订单**（不是接系统的「你该」） |
| **厨师** | 接单方：其他玩家（服务员/编剧/行者）、势力 NPC、或你雇的 Studio 成员 |
| **厨房（灶台、食材、规矩）** | **系统** — 托管报酬、验收熟度、卫生标准，**不决定你点啥** |
| **上菜** | 交付：一段可玩的经历、一件物品、一段剧情、一项能力成长 |
| **账单** | 你付的代价：时间、货币、机会成本 |
| **吃后的饱足感** | **与订单绑定的成长** — 只有你点的菜才加你想加的「营养」 |

```
        ┌─────────────┐
        │   玩家      │  「我要一份：灰烬港线索，重辣（高风险），
        │  （食客）   │   少盐（别太长），预算 200 灯油」
        └──────┬──────┘
               │ 点菜（创建订单）
               ▼
        ┌─────────────┐
        │   菜单系统   │  结构化你的欲望，不是替你选
        └──────┬──────┘
               │ 进入厨房队列
               ▼
        ┌─────────────┐
        │   厨师      │  按单制作（玩家/NPC/编剧）
        └──────┬──────┘
               │ 出菜
               ▼
        ┌─────────────┐
        │ 系统（厨房） │  验收：熟没熟、有没有毒、分账
        └──────┬──────┘
               │
               ▼
        玩家品尝 → 成长记在「我自己点的」账上
```

## 四、玩家怎么「在乎自己」—— 点菜界面（核心玩法）

玩家打开的不是「任务列表」，而是 **「我要」** 页：

### 4.1 先问三个问题（引导，非强制）

1. **我现在饿在哪？**（缺什么：情报 / 物资 / 声望 / 陪伴 / 刺激）  
2. **我想吃什么口味？**（风险偏好、叙事基调、单人还是协作）  
3. **我愿意付多少？**（货币、时间、愿意承担的后果）

### 4.2 菜单结构（示例）

| 栏目 | 玩家选择 | 系统作用 |
|------|----------|----------|
| **主菜** | 目标类型：调查 / 护送 / 探索 / 社交 / 经营… | 提供合法原子，不荐「今日必吃」 |
| **口味** | 轻松 / 沉重 / 幽默 / 恐怖 / 烧脑 | 影响匹配厨师与文案基调 |
| **份量** | 短篇 30min / 中篇 2h / 长篇连载 | 影响报酬与周期 |
| **忌口** | 不要剧透 X、不要 PVP、不要夜间 | 硬约束，厨师必须遵守 |
| **预算** | 愿付报酬区间 | 托管，厨房扣款 |

确认后生成 **「我的订单」**（Player-Initiated Order），**不是 System Quest**。

### 4.3 成长如何绑定「自己点的」

- 经验/声望/能力树：**只有完成「我点的单」才加对应维度**  
- 系统挂在公告栏的新手单（若玩家自愿接）**不计入主成长线**，或极少 —— 帮助页只指路「怎么点菜」，不提供终身饭碗  
- 角色卡可显示：**「你最近常点的口味」** → 世界开始用你的选择定义你是谁，而不是设计师定义的职业

## 五、厨师是谁？菜谁来做？

| 厨师类型 | 说明 | 与既有架构 |
|----------|------|------------|
| **玩家厨师** | 接别人的点菜单赚钱 | 服务单 / 行者 / 编剧 |
| **势力厨房** | 潮灯商会、拾遗院有招牌菜（固定风味） | NPC 势力，但**仍须玩家主动点** |
| **自雇厨师** | 花报酬雇编剧/Studio 为你定制 | B₁/B₂、服务市场 |
| **自助厨房（后期）** | 学会 Blueprint 后自己下厨 | SDK / 方案工作台 |

关键：**即使是 NPC 做菜，也要玩家先点菜** —— 没有「路过自动接任务」。

## 六、系统（厨房）做什么、不做什么

### 做

- 菜单语法（什么组合合法）  
- 托管与分账  
- 熟度验收（订单是否按忌口完成）  
- 厨房卫生（防刷、防毒、防诈骗）  
- 馆规（退款、评价、信誉）  
- **系统邮箱**：发放系统奖励、成就庆祝、重要公告（玩家**主动打开**才看见，见 §7.4）  
- **成就门槛**：玩家经历自然累积后触发的里程碑庆祝 + **可选拓展提示**（见 §7.5）  

### 不做

- **不派「你该去哪」、不设主线**  
- **不假装关心玩家成长**  
- **不推荐「今日必做」绑架在线**（可有中立行情榜，不是任务）  
- **订阅前不推送**（见 §7.2）  

系统像 **美团的后台 + 厨房法规**，不像 **班主任的作业本**。

## 七、无主线：悬赏栏 + 公告栏，玩家自取

**我们没有主线。** 成长不靠系统安排的剧情线或任务树，只靠玩家自己在世界里探索、自己点菜。

### 7.1 系统订单放在哪？

系统可以发一些**偏新手、偏简单**的单（熟悉操作、认识入口），但：

| 原则 | 说明 |
|------|------|
| **不进主线** | 没有「当前章节」「必做任务」；系统单只是公告/悬赏池里的一条 |
| **放悬赏栏 / 公告栏** | 和玩家发的单混在一起展示；**挂上去，谁爱接谁接** |
| **完全自愿** | 不接、跳过、先逛别的——都行；爱怎么体验就怎么体验 |
| **不追着喂** | 系统不弹窗催、不锁功能逼你接新手单 |

类比：餐厅门口贴了几张「今日推荐」小纸条，不是服务员拽着你必须点。

### 7.2 订阅前：零推送

在玩家**没有订阅某个产品/创作者/频道**之前：

| 做 | 不做 |
|----|------|
| 悬赏栏、公告栏、**系统邮箱** **被动展示**（他打开才看见） | **任何主动推送**（通知、弹窗、浏览器推送催你上线） |
| 帮助页 + 简单入门提示说明入口与基本操作 | 根据行为「猜你想做什么」并提醒 |
| 他探索到的内容 = 他该看见的 | 未订阅对象的动态推到他脸上 |

**订阅** = 玩家明确说「我想关注这个」；之后才允许该来源的更新通知（且仍应可关、可静音）。

全靠自己探索；愿意深挖的人自然会找到「我要」、悬赏、店铺、蓝图编辑器。

### 7.3 帮助页：只指路，不包办

探索型产品仍需要**帮助页**（或等价的「怎么开始」），但职责要窄：

**只回答：**

- 游戏/世界的**主入口在哪**（例如：我要、悬赏栏、地图、店铺）
- **接下来可以往哪走**（几条可选路径，不指定唯一正确路线）
- 术语极简说明（点菜、接单、蓝图、授权 B₂ 等——各一句）

**不回答 / 不做：**

- 不代替玩家决定成长路线
- 不用长篇教程锁死「第一步必须点 A」
- 不把系统新手单写成「请先完成以下 5 步」

帮助页 = **路牌**，不是 **导游全程讲解**。

**入门简单提示**（与帮助页配合，可更轻、更短）：

- 首次进入或关键界面：一两句「你可以先去悬赏栏看看 / 打开『我要』点一单」  
- 提示可关闭、可不再显示；**不锁操作、不强制点完教程**  
- 职责与帮助页相同：**指路下一步**，不替玩家选路线  

### 7.4 系统邮箱与背包

网页文字向的产品里，物品多以文本条目存在，**背包一般不设容量上限**——玩家正常游玩很少遇到「装不下」。

| 模块 | 定位 | 说明 |
|------|------|------|
| **背包** | 随身持有物 | **默认无上限**（或上限极高到可忽略）；直接入包为主路径 |
| **系统邮箱** | 系统→玩家的收件箱 | 玩家**自己点开**才读；**不是推送** |

**邮箱用来放什么：**

1. **待领取奖励** — 活动补偿、新手礼包、系统单报酬、**成就奖励**等；**必须玩家手动点「领取」** 才进背包  
2. **成就庆祝信** — 达到里程碑时的祝贺文案（见 §7.5）；可附带奖励，同样需手动领取  
3. **重要系统消息** — 版本更新说明、规则变更、馆规公告  
4. **（极少触发）溢出兜底** — 若未来某类物品需单独逻辑可暂存；**不作为常规玩法**

**领取规则：**

```
系统判定达成 → 奖励/信件进入邮箱（待领取）
                    │
            玩家打开邮箱，看到未读
                    │
            点击「领取」→ 物品进无上限背包
                    │
            纯祝贺无奖的信：点「已读」即可
```

- **不自动进背包** — 让玩家有意识「我拿到了什么」，也避免后台静默改状态  
- 未领取的奖励**一直留在邮箱**，不过期消失（除非极少数限时活动另行约定）

**与「零推送」的关系：**

- 邮箱有新信 ≠ 弹窗催你上线；导航上可有未读角标，玩家愿意时点进去  
- 未订阅前：邮箱里只有**系统级**内容（奖励、成就庆祝、更新、馆规），不会有创作者/店铺的订阅动态  

### 7.5 成就门槛：庆祝 + 拓展提示（不派活）

玩家经过一段时间、积累一定经历后，系统可设一批 **成就门槛**（门）——不是日常任务，而是**自然玩出来的里程碑**。

**门槛从哪来：**

| 类型 | 示例（门槛） | 说明 |
|------|----------------|------|
| 点菜经历 | 首次完成自点订单、累计点过 3 种口味 | 绑定「我自己点的」 |
| 厨师经历 | 首次接单交付、累计完成 N 单他人委托 | 双身份都可有成就 |
| 探索经历 | 逛过店铺、打开过蓝图页、订阅过第一个创作者 | 鼓励发现入口，不强制顺序 |
| 口味谱 | 某一维度雷达达到阈值 | 与 §8 口味谱联动 |

**达成时系统做什么：**

1. **庆祝信息** — 一封系统邮箱信：祝贺文案（「你第一次把单点熟了」），语气像馆子里的贺词，不像班主任批作业  
2. **可选奖励** — 若有，随信附上，**手动领取**（§7.4）  
3. **拓展提示（关键）** — 信末附 **2～3 条可选方向**，只提示「哪里还能延展」，**不指定现在必须去做什么**

**拓展提示怎么写（对 / 错）：**

| ✅ 可以 | ❌ 不要 |
|---------|---------|
| 「有人接下来会去**悬赏栏**接别人的单试试厨师身份」 | 「请立即前往悬赏栏完成下一任务」 |
| 「**店铺**里偶尔能发现别人上架的菜」 | 「你现在必须购买 X」 |
| 「口味偏调查的话，**我要**里可以点更辣的份量」 | 「主线已解锁，点击继续」 |

原则：**指路多条岔口，不替你选路、不锁下一步。**

**与主线、推送的边界：**

- 成就 **不是主线** — 没有「成就树必须清完」；未达成的门槛不展示剧透式催促  
- 庆祝信进 **邮箱** — 玩家打开才看见；不做全屏弹窗（导航未读角标可保留）  
- 拓展提示 = 成就时刻的**一次性路牌**，不是持续派单  

### 7.6 与「潮灯协议栈」的关系

| 旧默认 | 点菜式 |
|--------|--------|
| 系统 `system_daily` 派单、有主线 | **无主线**；系统单仅**公告/悬赏栏展示**，自取 |
| 订单池以系统货源为主 | 订单池以 **玩家点的单** 为主 |
| 成长 = 清任务列表 | 成长 = **味觉谱系**（你常点什么，你就成为什么） |
| 未订阅也推送 | **订阅前零推送**；系统邮箱被动查阅 |
| 背包容量卡成长 | **文本背包默认无上限**；奖励进邮箱，**手动领取**入包 |
| 成就 = 清成就列表 | **门槛里程碑** + 庆祝信 + 可选拓展提示，不派活 |
| Studio 做完整游戏卖 | 仍可并存：买「一整桌宴席」（Game）；日常用点菜 |

**统一句**：  
协议栈不变；**发起方从系统改为玩家**；系统单从「派给你」改为「贴在栏上」。

## 八、新奇观点：**「成长即口味谱」**

不做职业树（战士/法师），做 **口味雷达图**：

```
        调查
          ▲
    叙事 ◄─┼─► 风险
          │
        收集
```

- 你点的单越多越「辣」，世界给你更多高风险委托可选  
- 你总点「清淡叙事」，解锁的是编剧型厨师与文库  
- **没有人替你规划 60 级路线**；你的订单史就是履历  

这比「拒接系统任务」更进一步：把 **身份认同** 从策划表移到 **玩家自己的选择史**。

## 九、基础循环（可玩的一日）

```
登录
  → 打开「我要」，不是「任务板」
  → 根据当前饿感点一单（或浏览别人已点的单去当厨师）
  → 等待 / 游玩 / 出菜
  → 结算：成长加在自点维度 + 评价厨师
  → 饱足或没吃饱 → 下次再点，不补系统剩饭
```

**双身份同一天**：

- 中午：我点了一单调查（食客）  
- 晚上：我接了两单别人点的护送（厨师）  

谋生当厨师，成长当食客 —— **都主动**。

## 十、风险与边界

| 风险 | 对策 |
|------|------|
| 选择瘫痪（不知道点啥） | 新手「试吃套餐」：三道小样，仍算自点 |
| 厨房无人接单 | 动态加价、系统中立厨师托底（贵且平淡，不抢成长） |
| 全点高风险崩体验 | 口味谱软引导，不硬拦 |
| 不知道入口在哪 | **帮助页** + **入门简单提示**（可关），只指路各入口 |
| 系统奖励无处领 | **系统邮箱**待领取；点「领取」后进**无上限背包** |
| 玩久了不知道还能干啥 | **成就庆祝信**附可选拓展方向，不指定必做 |
| 公告栏没人接新手单 | 单一直挂着即可；不推送、不锁功能；玩家探索到再接 |

## 十一、MVP 可验证什么

1. **无主线模块**；系统新手单只进 **悬赏栏/公告栏**  
2. **订阅前零推送**；通知默认全关  
3. **帮助页** + **首次入门提示**（可关）：入口指路 + 3 条可选路径  
4. **系统邮箱**：奖励**手动领取** + 1 条更新说明示例；背包无上限  
5. **3～5 个成就门槛** + 庆祝信（含拓展提示文案，不派活）  
6. **「我要」点菜页** + 3 种主菜模板  
7. 1 类玩家厨师可接单；完成自点订单才加「口味经验」  
8. 问玩家：庆祝信里的拓展提示是否「有启发但不强迫」？

## 十三、小结

| 旧范式 | 新范式 |
|--------|--------|
| 系统派单、有主线 | **无主线；玩家点菜；系统单挂栏自取** |
| 系统在乎你（假） | **你自己在乎** |
| 清任务成长 | **口味谱成长** |
| 未订阅也推送 | **订阅前零推送** |
| 系统 = 老板 | **系统 = 厨房与馆规 + 悬赏/公告栏 + 系统邮箱** |
| 背包满、领不了奖 | **文本背包无上限**；邮箱待领取，手动入包 |
| 成就 = 肝清单 | **里程碑庆祝** + 拓展岔口提示，不派活 |
| 玩家 = 打工 | **玩家 = 食客（+ 可选厨师）；帮助页与成就信只指路** |

> 你来馆里， porque **你饿了**；不是 porque **电话响了**。栏上贴着推荐，你爱看不看；没订阅之前，厨房也不会给你打电话。
