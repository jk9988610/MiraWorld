# 执行在场与场次表演：怎么体现「正在工作」与「有人在场」

> 状态：履约可见性 + 同步场次 + 开发者配合  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、问题

1. **动作执行人**（厨师、骑手、演员、教师）如何让人看见「我在工作」？  
2. **必须凑人的场合**（课堂、演唱会、脱口秀、拍戏）如何体现 **参与人**？  
3. **导演、演员、剧本** —— 怎么「就位」、怎么「演」？  
4. **无法预料的玩家发挥**，开发者该设计什么来配合？

---

## 二、总原则：默认异步证明，同步是例外

| 默认 | 例外 |
|------|------|
| 用 **订单节点 + 状态 + 痕迹** 证明「干过活」 | 主办方 **预约场次**，才开短时间同步厅 |
| 观众/学生可以 **事后参与**（录像、摘要、作业） | 峰值 30～60 分钟同步，**不强制全服在线** |

**口诀：平时靠 **节点留痕**；专场靠 **场次台本**；即兴靠 **检查点 + 导演裁**。**

与 `04` `11` `12` 一致：**信箱错时为主；会议厅是香料，不是主菜。**

## 三、动作执行人：如何体现「我在工作」？

不做法师站桩动画，用 **L2 可查证信号**。

### 3.1 五种「在岗」信号（可叠加）

| 信号 | 谁看见 | 说明 |
|------|--------|------|
| **① 个人状态** | 名片访客 | 「进行中：烹饪子单 #8842」`22` |
| **② 订单里程碑** | 雇主/顾客 | 时间戳节点：接单→备料→出餐→送达 |
| **③ 地点在职标** | 进店的人 | 店铺页：「厨师小李 · 当班中」 |
| **④ 工作痕迹** | 地点访客 | 「后厨灯还亮着」（轻量 L2 或 L3 痕迹 `03`） |
| **⑤ 当班开关** | 系统派单 | 骑手打开「接单中」才进池（`01`） |

### 3.2 厨师 / 骑手示例

```
顾客看见：
  订单详情
    18:02 小李接单
    18:15 备料完成
    18:28 已出餐
    18:40 运送中（骑手小王）

小李自己看见：
  「我的」→ 进行中工单 + 下一步按钮「出餐」
```

**不是**实时看小李切菜，而是 **节点推进 + 可选一句 L3**（「汤还温着」）。

### 3.3 「装在工作」怎么办？

| 风险 | 馆规 |
|------|------|
| 只改状态不出餐 | 里程碑须 **L2 动作**（扣库存、产出 item）才能点完成 |
| 长期挂「当班」不接单 | 当班超时无单自动下线 |
| 虚假痕迹 | 痕迹绑 `order_id`；无单不留「在职」硬标 |

## 四、必须「凑人」的场合：三种参与档

课堂、演唱会、脱口秀、拍戏 —— 需求不同，用 **同一套「场次 session」**，开不同 **参与档**。

### 4.1 场次（session）是什么

```
session
├── session_id
├── host_id          # 教师 / 导演 / 主厨 / 主办方
├── type             # class | concert | talk | shoot | meeting
├── blueprint_id     # 台本 / 课程大纲（可复用 Blueprint）
├── window_start/end # 同步窗口（真实时间）
├── venue_location_id
├── roles[]          # 角色槽：教师、演员A、观众…
└── status           # scheduled | live | archived
```

### 4.2 三档参与（开发者按类型选）

| 档位 | 名称 | 课堂 | 演唱会 | 脱口秀 | 拍戏 |
|------|------|------|--------|--------|------|
| **A 异步** | 事后参与 | 看录播摘要交作业 | 买票看 **归档 transcript** | 读段子合集 + 留言 | 看成片 / 读剧本杀复盘 |
| **B 错峰** | 窗内签到 | 开放 24h 内交「到课打卡」+ 作业 | 窗内购票，演出后领纪念品 | 窗内投递「接梗」供演员选用 | 窗内完成 **分场 cues**（不必同时） |
| **C 同步** | 直播厅 | 可选 1h **文字教室** | 峰值 30min **同步厅** 弹幕/鼓掌 | 现场观众槽（限人数） | 关键场 **同时在线** 对词（可选） |

**MVP 建议：** 先做 **A + B**；**C 只做小场**，限人数。

### 4.3 参与人如何体现「来过」

不靠「同时在线人数」，靠 **可验证记录**：

| 记录 | 字段 | 展示 |
|------|------|------|
| **购票 / 报名** | `session_attendee` | 「已报名」 |
| **签到** | `checked_in_at` | 「曾到场」徽章 |
| **完成 cue** | `cue_log` | 「饰：巡街吏 · 完成 3/3 场」 |
| **观众留痕** | `applause` / 短评 | 「127 人曾鼓掌」 |
| **归档** | `transcript_id` | 未到场者可 **异步阅读** |

**课堂：** 学生名单 = 报名 + 作业提交记录，不要求同时打开页面。  
**演唱会：** 峰值可同步；没赶上的人看 **馆报摘要 + 录音式文字流**。  
**脱口秀：** 观众「接梗」异步投递；演员窗内选用 → 写入 transcript。

## 五、导演拍戏：就位与执行剧本

用 **场次台本（Runsheet）** —— Blueprint 的 **多角色公演版**。

### 5.1 角色与就位

```
Runsheet（绑 session_id）
├── role: director    → 用户甲（就位 ✓）
├── role: actor_lead  → 用户乙（就位 ✓）
├── role: actor_2     → 用户丙（未就位 · 截止前 2h）
├── role: extra       → 空槽 ×3（可公开报名）
└── role: audience    → 开放购票
```

**就位 =** 接受角色槽 + 在截止前点 **「确认就位」**（L2）。  
未就位 → **替补池** 或 **NPC 垫场**（`17` 系统托底叙事）。

### 5.2 剧本动作 = Cue（提示点）

不是自由实时 RP 一整场，而是 **一串可验收的 cues**：

| cue_type | 执行人 | 动作 | 系统验收 |
|----------|--------|------|----------|
| `ENTER` | 演员 | 点「入场」+ 可选一句台词 | 时间窗内、角色匹配 |
| `SAY` | 演员 | 提交台词（可限字数 / 给范例） | 非空；敏感词 |
| `PROP` | 演员 | 消耗背包 `item_prop` 或店供道具 | `has(item)` |
| `MOVE` | 演员 | 选 `location_id`「到场」 | 打卡该地点 |
| `MARK` | 导演 | 点「过」/「重拍」 | 导演权限 |
| `IMPROV` | 演员 | **开放框**（即兴槽） | 导演 **批准** 后入账 |

```
场次 1 · 巷口对峙
  cue 1  ENTER   actor_lead
  cue 2  SAY     actor_lead   提示：「你不该来。」
  cue 3  ENTER   actor_2
  cue 4  IMPROV  actor_2      # 即兴，导演裁
  cue 5  MARK    director     # 收工本场
```

**异步拍戏：** 每个 cue 有 **独立截止**（如 48h）；演员错时完成；导演异步批 IMPROV。

### 5.3 导演面板

```
【本场 Runsheet】
  进度 4/7 · 演员乙 待完成 cue 4
  [ 批准即兴 ] [ 插入新 cue ] [ 归档本场 ]

【参与人】
  导演：甲 · 主演：乙 ✓ 丙 ✓ · 群演：2/3
  观众：已售 40 票 · 归档后可看
```

## 六、无法预料的执行内容：开发者怎么配合？

玩家总会 **即兴、跑偏、少人来**。不要试图模拟每一个动作，设计 **检查点 + 裁量权 + 托底**。

### 6.1 四层配合（从硬到软）

```
┌─────────────────────────────────────────┐
│ ④ 归档与回放 — 没赶上的人仍能「参与」      │
├─────────────────────────────────────────┤
│ ③ 裁量层 — 导演/教师/店主 批准即兴        │
├─────────────────────────────────────────┤
│ ② 检查点 — 必须完成的 cue / 里程碑        │
├─────────────────────────────────────────┤
│ ① 模板 — 官方 session 类型 + Runsheet 空壳 │
└─────────────────────────────────────────┘
```

### 6.2 开发者提供的「内容积木」

| 积木 | 用途 | 例子 |
|------|------|------|
| **session 类型模板** | 一键开课堂/演出/拍摄 | `template_class_1h` |
| **Runsheet 空壳** | 导演只填角色和 cues | 5 场戏 × 每场 3 cue |
| **里程碑订单** | 非表演类工作 | 必须：出餐、送达、交作业 |
| **IMPROV 槽** | 允许不可预料 | 演员写，导演批 |
| **分支 cue** | 常见跑偏 | IF 演员选 A → cue 5a ELSE cue 5b |
| **NPC 垫场** | 人不够 | 系统念旁白、馆驿卒补群演 |
| **transcript 归档** | 异步观众 | 演出结束生成文字实录 |
| **软目标** | 不失败仅影响评价 | 「尽量 10 人前完成」— 仅成就 |

### 6.3 硬验收 vs 软评价

| 类型 | 设计 | 不可预料时 |
|------|------|------------|
| **硬** | 必须完成 cue / 扣道具 / 到地点 | 超时 → 替补 / NPC / 场次取消退款 |
| **软** | 台词好不好、气氛热不热 | 观众鼓掌数、导演评星、不入馆规 |

与 `13` 一致：**罚的是硬承诺；软的是艺术。**

### 6.4 教师课堂（开发者视角）

```
模板：class_session
  硬：window 内签到 1 次 + 作业 item 提交
  软：课堂讨论质量（教师评星）
  同步（可选）：1h 文字室，教师发题，学生异步跟帖
  未同步：教师发「讲义信」+ 学生信箱交作业
```

### 6.5 演唱会 / 脱口秀

```
硬：购票记录 + 窗内至少 1 次「在场」打卡（或看归档满 5 分钟）
软：弹幕、鼓掌、接梗被选中
峰值同步：限 50 人进「现场厅」；其余卖 **异步回放票**
```

## 七、和订单、职业的统一

| 场景 | 底层仍是什么 |
|------|----------------|
| 厨师做菜 | **商品单** 里程碑（`23`） |
| 骑手送餐 | **配送子单** 状态（`24`） |
| 演员拍戏 | **服务单 / session cues** |
| 教师上课 | **session + 作业交付物** |
| 律师评审 | **异步投票窗**（`09` `14`） |

**执行人都是「接了一个有检查点的活」**；差别只在检查点是 **扣面** 还是 **念台词**。

## 八、MVP 建议

| 做 | 不做 |
|----|------|
| 订单里程碑 + 个人「进行中」状态 | 全服实时动作同步 |
| 1 种 session 模板（如 talk 或 shoot） | 十种演出类型 |
| Runsheet：ENTER / SAY / MARK | 自由无结构 RP 一整夜 |
| 归档 transcript 异步看 | 强制全员同步 2h |
| 导演批准 IMPROV 槽 | AI 实时生成整剧 |
| NPC 垫场 1 种 | 复杂动捕 |

## 十、小结

| 问题 | 答案 |
|------|------|
| 怎么体现正在工作？ | **状态 + 订单里程碑 + 当班标 + 可选痕迹** |
| 课堂/演唱会怎么体现参与？ | **场次 session：报名、签到、cue 记录、归档回放** |
| 演员怎么就位、演剧本？ | **Runsheet 角色槽 + cue 串；就位=确认角色** |
| 不可预料怎么办？ | **IMPROV 槽 + 导演裁 + 分支 cue + NPC 垫 + 软目标** |
| 开发者做什么？ | **session 模板、Runsheet 空壳、检查点、归档** — 不模拟每个动作 |

> 平时让人看见你在干活，靠订单上的勾；  
> 专场让人看见你在场，靠场次里的名和 cue；  
> 即兴的部分，留给导演批、系统记、没赶上的人读归档。
