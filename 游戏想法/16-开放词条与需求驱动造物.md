# 开放词条与需求驱动造物

> 状态：物品百科 + 供需机制  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、问题

创作者搭了一个 **厨房** 场景，但不可能穷举所有厨具：  
玩家想要一把 **「弯柄汤勺」**——商城没有、蓝图没写、设计者没想到。

**线上文字游戏的解法不是「仿真批发」**，而是：

> **让词条先存在 → 能被搜到 → 能买到或能订做 → 能进背包 → 能完成订单/配方。**

批不批量无所谓；**`item_id` 在馆里挂号** 才是一切的前提。

---

## 二、核心原则

| 原则 | 说明 |
|------|------|
| **词条优先** | 先有 `item_id`，再有库存；没有货 ≠ 没有这个词 |
| **需求驱动** | 玩家想要 → 触发造物链，不是设计者预先列全表 |
| **线上原生** | 数字物品可复制；「量产」= 库存 +1 或无限副本 |
| **硬用法** | 只有 **百科登记** 的物品能进配方/订单验收（`13` L1） |
| **软名字** | 玩家口语「那把弯勺子」→ 系统匹配或新建规范词条 |

## 三、物品三层（谁能造什么）

```
┌─────────────────────────────────────────────────────────┐
│  T0 核心词条（设计方）                                    │
│  世界百科必备：盐、灯油、绷带、通用锅铲…                   │
│  任何厨房场景默认可引用                                    │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  T1 模板词条（创作者 / B₁）                               │
│  在「厨房模板」里选厨具类 + 填参数：材质、势力、名称        │
│  沙盒校验后入库，可挂店铺 SKU                               │
└───────────────────────────┬─────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────┐
│  T2 涌现词条（玩家需求触发）                               │
│  商城没有 → 求购 / 订制 / 系统铸造（见 §四）                │
│  须过馆规：标签、经济上限、不破坏平衡                        │
└─────────────────────────────────────────────────────────┘
```

**设计者想不到的厨具，大多从 T2 长出来。**

## 四、玩家想要一件东西：标准流程

```
玩家需要 item_X 完成任务（订单/配方/「我要」忌口）
        │
        ▼
① 搜商城 / 百科 / 店铺
        │
   ┌────┴────┐
   │ 有卖    │ 无卖但词条存在          │ 词条都不存在
   ▼         ▼                        ▼
 购买      ② 求购/订制               ③ 申请新词条
           │                        │
           ├─ 工匠代工单              ├─ 系统快速铸造（简单物）
           ├─ 系统铸造（标准件）       ├─ 工匠接单定义新 item
           └─ 等 B₁ 上架 SKU          └─ 投票/审核后入百科（高级物）
        │
        ▼
④ 进背包（手动领或自动）
        │
        ▼
⑤ 用于订单验收 / 配方消耗 / 交付
```

### 4.1 ① 商城有卖

最直接：买 SKU → 库/背包 → 使用。  
（`01` 数字商品单 / 二手 / 店铺）

### 4.2 ② 词条存在，但没货

百科里已有 `item_ladle_curved`「弯柄汤勺」，只是 **库存 0** 或 **无人上架**：

| 路径 | 谁做 | 异步做法 |
|------|------|----------|
| **挂单求购** | 买家发求购单 | 限价单等工匠接单（`01` §18.6） |
| **订制代工** | 工匠 | 「按词条做 1 把」服务单 + 材料（`01` 定制代工） |
| **系统铸造** | 系统 | 标准件、低价、有冷却；扣灯油即时 +1（见 §5） |
| **批量生产** | 作坊主 | 工匠接单「做 10 把」→ 上架店铺；数字上就是 stock=10 |

玩家体验：「馆里认这把勺子，只是此刻没人卖——我可以喊人做。」

### 4.3 ③ 词条不存在（设计者没想到）

玩家搜「弯柄汤勺」→ **无匹配** → 进入 **「提请新词条」**：

```
玩家填写：
  · 想要的名称（口语）
  · 用途说明（完成哪类订单 / 哪个厨房场景）
  · 建议分类：厨具 / 工具 / 材料…
        │
        ▼
系统尝试：
  A. 模糊匹配已有词条（「是不是指 锅铲？」）
  B. 若确认是新物 → 走「铸造申请」
        │
        ├─ 简单标准件 → 系统即时铸造 item_id（§5）
        ├─ 需配方 → 生成「工匠订制单」进订单池
        └─ 影响大/新标签 → B₁ 方案审核 或 馆规投票（后期）
        │
        ▼
新 item_id 写入百科（T2）→ 此后全服可搜、可卖、可用于验收
```

**关键：一旦 `item_id` 诞生，就进入 L1 世界——不是私有的假道具。**

## 五、系统铸造 vs 工匠订制（怎么选）

| | **系统铸造** | **工匠订制** |
|--|--------------|--------------|
| **适合** | 通用厨具、标准工具、低影响消耗品 | 命名独特、需叙事、高价、带词条属性 |
| **速度** | 即时或短冷却 | 异步订单（`04` 信箱交付） |
| **成本** | 固定灯油 + 可能材料模板 | 玩家议价托管 |
| **限制** | 白名单标签 `kitchen_utensil`；经济 cap | 须消耗材料；工匠技能标签 |
| **批量** | 点「做 10 个」= loop +10 stock | 工匠一次订单可做 N 个上架 |

**MVP 建议：**  
- 厨房场景绑定标签 **`kitchen_utensil`**  
- 该标签下 **系统可铸造 20 种基础厨具**（勺、铲、刀…）  
- **名称变体**（弯柄、长柄）→ 先映射到基础 id + `variant` 文案（L3），或触发 T2 新 id

## 六、厨房例子（端到端）

**场景：** 玩家接了一单「用厨房完成熬汤」，Blueprint 要求 `has(item_pot)` + `has(item_ladle)`。

1. 背包有锅，**没有勺**  
2. 打开 **灯市** 搜「汤勺」→ 无 SKU  
3. 打开 **百科** 搜「ladle」→ 有 `item_ladle` 但无人卖  
4. 点 **「订制一把」** → 发代工单，报酬 30 灯油  
5. 工匠 B 接单，消耗 `item_metal_scrap` ×1（系统验材料），异步交付  
6. 玩家邮箱领 `item_ladle` ×1 → 手动进背包  
7. 回厨房节点 → 系统验收通过 → 订单完成  

**若百科连 `ladle` 都没有：**  
3b. 点 **「提请厨具词条」** → 选分类厨具 → 系统铸造 `item_ladle` 入百科 → 同时生成一笔订制单或直接系统 +1（按平衡表）

**厨师台词（L3）：** 「这勺子弯得好看」——不影响验收；验收只看 `item_ladle`（L2）。

## 七、与「我要」点菜、订单、Blueprint 的衔接

| 模块 | 衔接 |
|------|------|
| **「我要」** | 忌口/工具需求可写「需要某类厨具」→ 系统展开为合法 tag |
| **Blueprint** | 节点 `RequireItem(id)` 只认百科 ID；缺物时 UI 链到 §四 流程 |
| **店铺** | 工匠做完可一键「上架 10 把」；SKU 绑 `item_id` |
| **二手** | 词条存在即可挂卖，即使全世界只有 1 把 |
| **律师** | 货不对板：SKU 承诺 `item_ladle_curved` 实际发 `item_ladle`（`09`） |

## 八、馆规与防滥造

| 风险 | 对策 |
|------|------|
| 刷无限神器 | 新词条须 tag + 经济审核；战斗物品不可 T2 自助铸造 |
| 垃圾词条洪水 | 每日提请上限；重复名合并 |
| 同名不同物 | 规范 `item_id`；显示名可重复但 id 唯一 |
| 工匠不接单 | 系统铸造托底（贵且平淡） |
| 设计者厨房缺 T0 | 场景发布时校验：至少链接 `kitchen_utensil` 标签池 |

## 九、MVP 建议

| 做 | 不做 |
|----|------|
| 百科 `item_id` + 标签 `kitchen_utensil` | 玩家任意起名即时神装 |
| 商城搜索 + 「无货 → 订制单」 | 全开放 T2 无审核 |
| 系统铸造 **10 种** 基础厨具 | 复杂 variant 树 |
| 缺物时 Blueprint UI 提示并链到订制 | 自动静默造物品 |

## 十一、小结

| 问题 | 答案 |
|------|------|
| 设计者想不到的道具？ | **玩家需求 → 词条入库（T2）** |
| 先做什么？ | **`item_id` 存在**，再谈卖不卖 |
| 没人卖？ | 求购 / **工匠订制单** / **系统铸造** |
| 批量？ | 数字 `stock += N` 即可 |
| 怎么用？ | 只有百科登记的 id 能过 **订单验收** |

> 厨房不必事先摆满每一把勺子。  
> 玩家说「我需要弯柄勺」——馆里先登记这个词，  
> 再有人做、有人卖、有人用它在灶前把汤搅热。
