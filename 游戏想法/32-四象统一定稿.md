# 四象统一定稿：人 · 地 · 事 · 物

> 状态：**全系统顶层规范**（取代分散名词）  
> 记录时间：2026-09-13  
> 原则：**能简化就简化**；新功能必须先能落进四象，否则不收录  

**口诀：人是谁，地在哪市，事是账，物在谁手。**

---

## 〇、为什么要有这一篇

此前已统一：

| 已统一 | 定稿 |
|--------|------|
| 钱 | **credits / 点**（`30`） |
| 地（地址） | **市** 一段；精确定位 **市 + 人**（`31`） |

本文把 **人、地、事、物** 全部收成 **四个母概念**，旧文档里的 SKU、店铺、馆规、悬赏、信箱……都 **映射进四象**，不再各起一套名字。

---

## 一、总览

```
                    ┌─────────┐
                    │  credits │  ← 横切：只有一种钱
                    └────┬────┘
         ┌──────────┼──────────┐
         ▼          ▼          ▼
      【人】      【地】      【物】
     Actor      Place      Thing
         │          │          │
         └────┬─────┴─────┬────┘
              ▼           ▼
            【事】
           Record
        （把一切发生连接起来）
```

| 象 | 英文键 | 一句话 | 玩家看见 |
|----|--------|--------|----------|
| **人** | `actor` | 谁在做/谁拥有 | 陈师傅、@雾桥阿青、系统 |
| **地** | `place` | 在哪座市 | 潮灯市 |
| **事** | `record` | 发生过什么 | 订单、通知、打卡、流水 |
| **物** | `thing` | 什么东西 | 标准汤面、一碗面 |

## 二、人 Actor

### 2.1 只有三类

| `kind` | 标识 | 例 | 有钱包？ |
|--------|------|-----|----------|
| `player` | `handle`（唯一） | `雾桥阿青` | ✅ `wallet_credits` |
| `npc` | `npc_id` | `npc_chen` | ❌（收款走订单分账） |
| `system` | 固定 `system` | 系统 | ❌ |

**统一引用（全 API 共用）：**

```json
{ "kind": "player", "id": "雾桥阿青" }
{ "kind": "npc", "id": "npc_chen", "display": "陈师傅" }
{ "kind": "system" }
```

简称 **ActorRef**。禁止再发明「行者」「店主 ID」「厨师 user_id」等多套指人方式——**都是 actor**。

### 2.2 玩家字段（MVP）

| 字段 | 说明 |
|------|------|
| `handle` | 登录、收信、名片（= 原 username） |
| `city` | 所在市，如 `潮灯市` |
| `wallet_credits` | 点 |
| `bio` | 简介（L3 文案） |

### 2.3 NPC

配置在 `locations.json` / `actors.json`；**店 = 某个 NPC**，不单独造「店铺实体」除非 v1.2 玩家开店（店主 = player actor）。

| 旧概念 | 现为 |
|--------|------|
| 行者 | `player` |
| 店主 / 厨师 | `actor`（player 或 npc） |
| 系统信箱发件人 | `system` |

---

## 三、地 Place

### 3.1 地址只有市

```json
{ "city": "潮灯市" }
```

### 3.2 精确定位 = 市 + 人

```json
{
  "city": "潮灯市",
  "actor": { "kind": "npc", "id": "npc_chen" }
}
```

**不再收录：** 区、街道、小区、格号、省国。

### 3.3 逛点 spot（可选，非地址）

| 字段 | 用途 |
|------|------|
| `spot_id` | 晚霞岸、栈桥 —— 文案与打卡彩蛋 |
| 记账 | 仍只写 `city`；`spot` 进 `record.payload` |

### 3.4 旧概念映射

| 旧 | 现为 |
|----|------|
| 地点节点 / 区 | `city` + 可选 `spot` |
| 家园锚点 | `player.city`（v1.3 不加门牌） |
| 配送地址 | `city` + 收件人 `actor` |

---

## 四、物 Thing

### 4.1 两层就够

| 层 | 叫什么 | 存什么 |
|----|--------|--------|
| **定义** | `item` | 世界里有什么（配置 `items.json`） |
| **持有** | `stack` | 谁手里有几个 |

```json
// 定义
{ "id": "item_noodle_bowl", "display": "一碗面" }

// 持有
{ "holder": { "kind": "player", "id": "雾桥阿青" }, "item_id": "item_noodle_bowl", "qty": 1 }
```

### 4.2 可买 = 挂单 offer（取代 SKU）

**不再强调 SKU 一词**；玩家看见「菜单行」= **offer**。

```json
{
  "id": "offer_standard_noodle",
  "seller": { "kind": "npc", "id": "npc_chen" },
  "place": { "city": "潮灯市" },
  "gives": { "item_id": "item_noodle_bowl", "qty": 1 },
  "price_credits": 15,
  "display": "标准汤面"
}
```

| 旧 | 现为 |
|----|------|
| SKU | **offer** |
| item / 词条 | **item**（定义） |
| 背包 | **stack** |
| 配方 | `offer` 或 `item.recipe`（MVP 可写死在 offer） |
| Blueprint | v3；未落地前 **不收录** |

### 4.3 物不参与地址

物挂在 **人** 上（stack），不挂在地上。

## 五、事 Record

### 5.1 一切「发生过」的都是 record

**一种表、多种 `type`**（或分表但同一套字段约定）。

| `type` | 玩家叫 | MVP | 连接 |
|--------|--------|-----|------|
| `order` | 订单 | ✅ | 人↔人，钱，物 |
| `message` | 通知/信 | ✅ | 人→人 |
| `visit` | 打卡 | ✅ | 人+地 |
| `ledger` | 流水 | ✅ | 人+钱（事的事） |
| `bounty` | 悬赏 | v2 | 人↔人，钱 |
| `vote` | 投票 | v2 | 人+事 |
| `job` | 招聘 | v1.5 | 人↔人 |

### 5.2 通用字段

```json
{
  "id": "rec_1024",
  "type": "order",
  "status": "escrowed | cooking | done | cancelled | ...",
  "actors": {
    "from": { "kind": "player", "id": "雾桥阿青" },
    "to":   { "kind": "npc", "id": "npc_chen" }
  },
  "place": { "city": "潮灯市" },
  "credits": { "amount": 15, "escrow": true },
  "things": [{ "item_id": "item_noodle_bowl", "qty": 1 }],
  "payload": {},
  "at": "2026-09-13T12:00:00Z"
}
```

| 旧 | 现为 |
|----|------|
| 订单 + 里程碑 | `order` + `payload.events[]` |
| 系统信箱 / 往来信 | `message`（`from`/`to` actor） |
| 托管 / 分账 | `order` + `ledger` |
| 打卡记录 | `visit` |
| 悬赏 / 招贤帖 | `bounty` / `job`（未来） |
| 馆规 / 平台规则 | **不是 record**，是配置文案 |

### 5.3 事的状态机（order 示例）

```
created → escrowed → processing → ready → completed → settled
```

一种 `type` 一套 `status` 枚举；**禁止**为每种玩法单独发明状态名，先映射到 `order` 或新 `type`。

## 六、横切：credits

| 规则 | 说明 |
|------|------|
| 唯一货币 | `wallet_credits`（整数） |
| 一切变动 | 必须有一条 `ledger` record |
| 托管 | `order.credits.escrow` |
| 禁止 | 第二货币、灯油当钱、现金提现 |

## 七、四象拼常见场景

| 场景 | 人 | 地 | 事 | 物 |
|------|----|----|----|-----|
| 注册 | player 新建 | city=潮灯市 | visit? | — |
| 点一碗面 | 玩家→陈师傅 | 潮灯市 | order | offer→stack |
| 出餐通知 | 系统→玩家 | — | message | — |
| 打卡晚霞岸 | 玩家 | 潮灯市 | visit(spot) | — |
| 分账 | 陈师傅→玩家钱包 | — | ledger | — |
| v2 悬赏 | 玩家A→玩家B | 潮灯市 | bounty | 可选 stack |
| v1.2 玩家开店 | player 作 seller | 潮灯市 | offer 上架 | item |

**发布会 v1.0 竖切：** 注册 → visit → order → message → stack。只用到四象的子集。

## 八、对未来功能的准入规则

新设定 **必须** 回答：

1. **人**：哪些 actor 参与？  
2. **地**：哪个 `city`？要不要 spot？  
3. **事**：哪种 `record.type`？  
4. **物**：哪个 `item` / `offer` / `stack`？  

**以下直接不收录：**

- 不能表达为四象之一的系统（如单独「信誉货币」→ 用 credits 或 player.payload）  
- 需要省/区/门牌才能描述的地址  
- 与四象平行的第五套命名（再发明「单」「帖」「券」作核心实体前，先映射到 record 或 item）

**可以收录的扩展方式：**

| 想加 | 做法 |
|------|------|
| 信誉 | `player.payload.reputation` 或 record 统计 |
| 执照 | `player.payload.badges[]` |
| 配送费 | `order.credits` 加一行 ledger |
| 势力 | `player.payload.faction`（标签，非地址） |
| 粉笔痕迹 | `record.type = trace`（v2） |

## 九、配置与代码布局

```
server/config/
  schema.json      # 四象字段约定（本文档机器可读摘要）
  locations.json   # 地：cities, spots
  actors.json      # 人：npc 表（可从 locations 拆出）
  items.json       # 物：item 定义
  offers.json      # 物：可买挂单（原 SKU）
```

数据库 MVP 核心表（逻辑名）：

| 表 | 象 |
|----|-----|
| `players` | 人 |
| `stacks` | 物 |
| `records` | 事（或 order/messages/visits/ledger 分表同构） |

**npc、city、item 定义** → 配置只读，不进 DB。

## 十、玩家帮助页（一段话）

> **人**：你和 NPC，用名字认。  
> **地**：只说哪座市，如潮灯市；找店找 **陈师傅**。  
> **事**：订单、通知、打卡，都在「记录」里。  
> **物**：背包里的东西；菜单上是 **挂单**。  
> **钱**：只有 **点**，不能提现。

## 十二、小结

| 象 | 母概念 | 技术主键 |
|----|--------|----------|
| 人 | ActorRef | `kind` + `id` |
| 地 | Place | `city`（+ 可选 `spot`） |
| 事 | Record | `type` + `status` + actors/place/credits/things |
| 物 | Item / Stack / Offer | `item_id`；买卖用 `offer` |

> 别再加第五套名词；  
> 新玩法先问：人谁、哪市、什么事、什么物——
