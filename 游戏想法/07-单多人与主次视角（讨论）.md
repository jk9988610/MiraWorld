## 一、要讨论什么

米拉世界已有 **个人钱包 · 公司 · 机构 · 店 · 日 tick**，但还缺三层「入口与节奏」设计：

| 层 | 问题 |
|----|------|
| **门控** | 进游戏前：新开/继续，单人/多人怎么选？ |
| **速度** | 借鉴 Victoria 3：**单人可调速，多人固定中间速** |
| **主次视角** | 同一角色有两条体验线：**公司线** 与 **个人线**；玩家自己定谁主谁次，或按时间表自然切换 |

本文只定 **产品与体验方向**，不写实现排期。

## 二、进门控：四选一

### 2.1 选项

进入游戏前（登录后、进潮灯市前）统一门控：

```
┌─────────────────────────────────────┐
│         米拉世界 · 选择存档          │
├─────────────────────────────────────┤
│  ○ 新的单人游戏                      │
│  ○ 继续单人游戏                      │
│  ○ 新的多人游戏                      │
│  ○ 继续多人游戏                      │
└─────────────────────────────────────┘
```

| 选项 | 含义（草案） |
|------|----------------|
| **新的单人游戏** | 新建 **私有世界实例**（或私有 city 沙盒）：只有该玩家的决策影响该实例 tick；可从头开店/公司 |
| **继续单人游戏** | 载入上次单人存档，恢复世界时钟与资产 |
| **新的多人游戏** | 进入 **共享城市**（现网潮灯市模式）：与其他玩家同一 economy tick、同一 Hub/市场 |
| **继续多人游戏** | 回到该玩家在共享城里的 handle / 公司 / 店 |

### 2.2 与现架构的关系

| 现网 | 门控后 |
|------|--------|
| 一个 DB、一座潮灯市、全员共享 tick | **多人** = 现模式；**单人** = 独立 `world_id` / `save_slot` + 独立 tick 驱动 |
| 玩家 = handle + 可选公司/店 | 不变；门控只决定 **世界实例** 与 **时钟策略** |
| cron 日 tick | 多人：服务端固定节奏；单人：玩家可调速（见 §三） |

**纪律：** 单人存档 **不得** 悄悄污染多人共享经济；多人 **不得** 因某玩家暂停而全服暂停。

### 2.3 待决

- [ ] 单人是否允许多存档槽（如 3 槽）？  
- [ ] 「新的多人游戏」是选 city 还是默认唯一潮灯市？  
- [ ] 单人世界是否仍跑 NPC 市民组（闭环自洽），还是缩成「教学沙盒」？  
- [ ] 单人 → 多人 **迁档** 要不要？（建议：**不做**，防经济串线）

## 三、速度：Victoria 3 式，单人多速、多人定速

### 3.1 参照

Victoria 3：**暂停 + 多档加速**；玩家按思考节奏推进 simulation。

米拉世界不是 RTS 帧同步，而是 **日 tick 经济仿真** — 速度 = **虚拟日与现实时间/操作的关系**。

### 3.2 规则（草案）

| 模式 | 速度 |
|------|------|
| **单人** | 玩家可调：**暂停 · 慢 · 中 · 快**（必要时加「极快」仅 SP） |
| **多人** | **固定中间速**：全员共享同一 `world_clock`；不可暂停全服 |

```
单人速度档（示例）
  暂停   → 不推进 tick；可改价、挂 offer、改配方
  慢     → 1 虚拟日 ≈ 30 分钟
  中     → 1 虚拟日 ≈ 10 分钟（默认）
  快     → 1 虚拟日 ≈ 3 分钟
  极快   → 仅 SP；用于试生产链 / smoke 式验收

多人
  锁定「中」→ 1 虚拟日 ≈ 10 分钟（与 cron 对齐，全服一致）
```

### 3.3 与 tick 的衔接

现有顺序（[06](./06-两层经济（L0 Hub + 成品市场）.md)）不变：

```
l0_tick → production → payroll → welfare → pop 采购 → institution procurement
```

**单人 `force tick`** 可保留为调试/加速手段；**多人** 仅服务端调度 + 可选 `X-Tick-Secret` 运维，玩家 UI **无 force**。

### 3.4 UI 提示

- 单人：顶栏或资本家页显示 **当前速度档 + 下一 tick 倒计时**  
- 多人：显示 **世界日** 与 **距下次城市 tick**，文案强调「与他人同频」

### 3.5 待决

- [ ] 单人「暂停」时，离线 auto_on / 生产是否冻结？（建议：**冻结**，与 Vic3 一致）  
- [ ] 多人中间速是否允许运营后台临时调档（维护窗口）？  
- [ ] 速度是否影响 **通知送达** 还是只影响 **经济 tick**？（建议：**只影响 tick**）

## 四、主次视角：公司线 vs 个人线

### 4.1 两个维度

同一 `player` 同时有两套「谁在主导体验」：

| 维度 | 主视角 = 公司 | 主视角 = 个人 |
|------|----------------|----------------|
| **钱** | 公司账、机构运营账、Hub 采购、工资与生产 | 个人钱包、日投领取、消费、委托 |
| **操作** | 生产页、挂成品市场、NPC 岗、机构 slot | 地图、背包、购 offer、委托、通知里的生活类 |
| **叙事语气** | 「董事会 / 厂长 / 运营」 | 「下班后的你 / 市民 handle」 |
| **默认页** | 资本家 · 生产 · 城市经营 | 地图 · 背包 · 我的店（顾客侧） |

**不是两个角色**，是 **同一 handle 的两副眼镜**。

### 4.2 两种维护方式（可并存，玩家自选）

#### 方式 A · 手动主次

设置里二选一或随时切换：

- **以公司为主**：底栏默认进资本家/生产；通知优先经营类；个人消费收进二级入口  
- **以个人为主**：底栏默认地图/背包；公司操作收进「上班去」入口  

适合：喜欢明确「现在在上班还是下班」的玩家。

#### 方式 B · 时间表自然切换（推荐长期默认）

**不分固定主次**，像现实一样按 **上班 / 下班 / 节假日** 自动换状态：

```text
life_schedule（草案）
  timezone
  work_windows[]     # 如 周一至五 09:00–18:00
  holidays[]         # 可选：全天 personal
  default_mode       # work_window 外 → personal
```

| 时段 | 自动状态 | UI 行为 |
|------|----------|---------|
| **上班窗口** | `focus=company` | 默认页、通知权重偏公司；仍可手动点地图 |
| **下班窗口** | `focus=personal` | 默认页偏生活；公司入口保留但不抢屏 |
| **节假日** | `focus=personal` 或玩家自定义 | 可设「加班日」例外 |

**口诀：时间表决定默认眼镜；玩家随时可手动 override 一次，override 不改表。**

与 [27 离线日程](./_archive/27-离线日程与自动当班.md) 的关系：

- **27** 管「离线时系统自动接单/当班」  
- **07 时间表** 管「在线时默认看哪条线、通知怎么排」  
- 可共用 `timezone` 与 `windows`，但 **职责分开**

### 4.3 与现有页面的映射

| 页面 | 公司主 | 个人主 |
|------|--------|--------|
| `/play/capital` | 首页级 | 二级 |
| `/play/production` | 首页级 | 「上班去」 |
| `/play/economy` | 并列 | 并列（城市是公共背景） |
| `/play/my-shop` | 管理侧突出 | 顾客/店主切换（已有 open/auto） |
| 地图 / 背包 / 委托 | 二级 | 首页级 |

### 4.4 待决

- [ ] 默认给新玩家：**手动主次** 还是 **时间表**？（建议：先 **手动**，解锁公司后引导开启时间表）  
- [ ] `focus=company` 时是否 **隐藏** 个人钱包数字，还是仅 **降权展示**？  
- [ ] Spotlight / 市民组叙事是否随 focus 换文案？（如上班时 Spotlight 偏「行业动态」）  
- [ ] 多人模式下，时间表是否 **仅影响 UI**，不影响 tick？（建议：**是**）

## 五、三者的组合矩阵

| | 单人 + 公司主 | 单人 + 个人主 | 单人 + 时间表 | 多人 + 任意 focus |
|--|----------------|----------------|----------------|---------------------|
| **速度** | 可调 | 可调 | 可调 | 固定中速 |
| **世界** | 私有实例 | 私有实例 | 私有实例 | 共享潮灯市 |
| **tick** | 本地/槽位驱动 | 同左 | 同左 | 服务端 cron |
| **典型玩家** | 试生产链、刷经营 | 慢节奏逛市 | 最贴近「上班下班」 | 与他人共市 |

## 六、对产品原则的检验（对齐 01）

| 01 检查项 | 本设计 |
|-----------|--------|
| 新功能是否只是 **决策 + 数字**？ | 门控/速度/视角 **不改经济公式**，只改 **实例、时钟、UI 权重** |
| 无玩家时城市能否自转？ | **多人**：必须；**单人暂停**：该实例冻结 |
| 不做 Victoria Pop 政治 | ✅ 只借 **速度 UX**，不做人口政治层 |
| 异步优先 | 多人固定中速 + 信箱通知，不逼同时在线 |
