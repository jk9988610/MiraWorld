# 文本世界的真实与叙事：该往现实走，还是往线上走？

> 状态：世界观与机制哲学  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、问题从哪来

厨师说：「这碗面材料从美国进口。」  
在文字游戏里：

- 读者**看不见**货柜、报关单、咬一口的口感  
- 「美国进口」可能只是 **一句台词**  
- 甚至材料本身也可以是 **叙事上的假** —— 这还挺幽默，但也暴露问题：**文本无法天然鉴别现实细节**

所以：**不该假装文字能模拟一切现实**；该选一种 **线上文字原生** 的「真实」定义。

---

## 二、三层真相（核心模型）

```
┌─────────────────────────────────────────────────────────┐
│  L3 叙事层（谁说都行）                                    │
│  厨师台词、粉笔字、信箱修辞、「据说美国进口」               │
│  → 不自动改游戏状态；可当 RP、可撒谎、可幽默               │
└───────────────────────────┬─────────────────────────────┘
                            │ 玩家自己信不信
┌───────────────────────────▼─────────────────────────────┐
│  L2 馆规层（系统可验）                                    │
│  订单完成、物品 ID、托管分账、打卡地点、Blueprint 交付      │
│  → 服务器日志；纠纷靠 `09` 评审团看硬证据                  │
└───────────────────────────┬─────────────────────────────┘
                            │ 绑定
┌───────────────────────────▼─────────────────────────────┐
│  L1 原子层（世界百科）                                    │
│  官方物品：`item_mist_salt`「雾晶盐」产地：潮灯港           │
│  → 只有百科登记过的属性，才算「系统承认的标签」              │
└─────────────────────────────────────────────────────────┘
```

| 层 | 现实类比 | 线上类比 |
|----|----------|----------|
| **L3 叙事** | 店员吹牛逼 | 商品详情里的小作文、用户评论 |
| **L2 馆规** | 合同、收据、平台托管 | 订单状态、库权益、`ledger` |
| **L1 原子** | 有 SKU 条码的商品 | 世界百科 `item_id` + 系统字段 |

**「美国进口」若只是 L3** —— 好笑、可扮演，**不算造假到可处罚**，除非 SKU 硬标签写了别的（`07` 描述与 Blueprint 一致）。

## 三、该往哪个方向走？

### 结论：**往线上原生走，用「馆规真实」替代「现实仿真」**

| 方向 | 做法 | 问题 |
|------|------|------|
| **往现实仿真** | 模拟产地、新鲜度、报关、味觉 | 文字装不下；易假；开发爆炸 |
| **往线上原生** | 只承认 **ID、状态、订单、标签** | 玩家要重新学「什么算数」 |
| **推荐：分层诚实** | 台词随便说；**硬属性看系统** | 与现有 `01` 软硬边界一致 |

> 不是「更像现实生活」，而是 **「更像可靠的线上交易与记录」**。

## 四、类比：一碗面在三种店里

| | 街头小店（纯叙事） | 连锁餐厅（馆规） | 平台外卖（MiraWorld） |
|--|-------------------|------------------|------------------------|
| 墙上写啥 | 「美国牛肉」——你信就吃 | 菜单有营养表，但很少人去查 | SKU 写「雾港盐 ×3」 |
| 什么算真 | 好吃就行 | 工商抽查 | **系统验收**：背包里有没有 `item_fog_salt` |
| 厨师吹牛 | 常态 | 投诉才管 | L3 随便；若 SKU 承诺「含雾港盐」而 Blueprint 没有 → **可举报**（`09` 案型 1） |
| 进口 | 无法验证 | 供应链票据 | **不模拟进口国**；模拟 **`origin: ashen_harbor` 百科标签** |

**美国进口** → 换成世界观内可验证的：**「拾遗院认证」「潮灯港仓单 #8842」** —— 后者可绑 `order_id` 或 `item` 元数据。

## 五、厨师做菜：线上原生版怎么写

### 5.1 错误方向（假现实）

```
厨师文案：「美国面粉、日本酱油」
系统：无法验证 → 玩家只能当笑话
纠纷：无法裁 → 律师团无从看卷宗
```

### 5.2 推荐方向（线上原生）

```
【硬】配方消耗 inventory：
  - item_fog_wheat ×2  （百科：产地 ashen_harbor）
  - item_tidelamp_soy ×1
【硬】产出：
  - item_noodle_bowl ×1  （绑定 crafted_by: chef_id, recipe_id）
【软】厨师上菜台词（L3）：
  「面汤用昨夜的雾，你信也好不信也好。」
【可选硬标签】若 SKU 承诺「商会认证」：
  - 必须 recipe 含 certification_flag
  - 否则按货不对板举报
```

| 玩家问 | 系统答什么 |
|--------|------------|
| 材料哪产的？ | 查物品百科 **`origin`** 字段（L1），不是厨师嘴（L3） |
| 好吃吗？ | 评价、口味谱（软） |
| 真有一碗面吗？ | 背包 `item_noodle_bowl` +1（L2） |

### 5.3 「材料是假的」也可以是有意设计

- **叙事谎**：厨师台词撒谎 → RP、幽默、不可靠叙述者  
- **欺诈案**：SKU **硬承诺** 与交付物不符 → 馆规介入（`09`）  
- **区别**：罚的是 **违背 L2 的合同**，不是 **违背 L3 的吹牛**

## 六、什么该仿真、什么该抽象

| 现实概念 | 文字游戏建议 | 线上替代物 |
|----------|--------------|------------|
| 美国进口 | 不仿真 | `origin: harbor_id` 或 `faction_cert` |
| 新鲜度 | 不仿真 | `crafted_at` 时间戳（若要腐坏再加规则） |
| 味道辣不辣 | 半软半硬 | 口味标签 + 玩家评价；硬约束用 `tone` 检测（`09` 案型 10） |
| 一碗面是否存在 | **硬** | `item_id` 进背包 |
| 厨师会不会做饭 | **硬** | 订单验收、服务单里程碑 |
| 店门口吹牛 | **软** | 粉笔字、台词，不验真伪 |
| 付款 | **硬** | 托管、`ledger` |
| 战争 | 不仿真兵力 | 世界季 + 贡献条（`12`） |

**规则：能进服务器的用 ID；进不了服务器的当文学。**

## 七、与现有文档的统一说法

| 文档 | 本条哲学 |
|------|----------|
| `01` 软硬交互 | 聊天吹进口 = 软；扣材料出物品 = 硬 |
| `07` SKU | 货架语言 L3；Blueprint 交付 L2 |
| `09` 律师 | 卷宗看硬证据；台词作背景不作唯一依据 |
| `03` 痕迹 | 粉笔 = L3；打卡 = L2 |
| `02` 点菜 | 「忌口」可硬；「氛围」可软 |
| `12` 世界季 | 天下大势 = 设计方 L2 flag，不是真实战争 |

## 八、给玩家的一句话（可放帮助页）

> **嘴上说的话，是故事；背包里的条目和订单上的记录，才是馆规。**  
> 我们不假装能尝出美国进口，但我们能证明：你付的灯油、你拿到的 `雾晶盐`，都在账上。

## 十、小结

| 问题 | 答案 |
|------|------|
| 现实细节搬不进文字？ | **承认**，不硬仿真 |
| 往哪走？ | **线上原生**：ID、订单、百科标签、托管 |
| 厨师说美国进口？ | 默认 **L3 叙事**；要可罚则绑 **L1/L2 标签** |
| 幽默的「假材料」？ | 保留在台词层；馆规只管 **硬承诺** |
| 类比 | 外卖看 **订单与菜品条目**，不看店员 **吹牛** |

> 文字游戏的「真实」，不是物理世界的复制品，  
> 而是 **一套大家都认账的线上馆规**。
