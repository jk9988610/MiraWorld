## 一、一句话

**化繁为简：核心只有生产与消费。**  
城市自己转；玩家是 **经营者**（带 handle），用资产在闭环里赚钱。  
不绕弯：无配送、无故事输出、无律师判决、无招贤应聘。

---

## 二、商品怎么到玩家手里（定稿）

```
买家点 offer → 扣点 → 卖家履约 → 通知 → 物进背包
```

**没有：** 骑手、配送、取餐 drama。

玩家 **确认收进背包**（`pickup`）；订单与委托 **一律通知**。

---

## 三、乌托邦双账本

| 账本 | 说明 |
|------|------|
| **内生** | 机构 ↔ 市民组：工资、消费、卖货（**必须自洽**） |
| **外生 · 城市福利** | 无岗市民 **最低生活补贴**（城市福利基金 + 乌托邦 grant） |
| **外生 · 玩家日投** | 资本家日投资金（规划；**不计入**市民平衡） |

市民钱 **不能** 从消费池凭空刷；**在岗** 靠 **最低工资以上** 的工资，**无岗** 靠 **温饱补贴**。见 [44](./44-机构编制与工资定稿.md)。

---

## 四、Actor 极简

| Actor | 职责 |
|-------|------|
| **玩家** | 生产决策（店/公司/offer/NPC 岗）；仅 handle，无市民标签 |
| **机构** | 生产、雇组、发薪 |
| **市民组** | 1000 人/组；消费 |

---

## 五、其它简化（仍有效）

| 领域 | 做法 |
|------|------|
| 通讯 | 系统 **通知**（经营结果） |
| 地址 | 市 + handle |
| 钱 | **点** / credits |
| 托底 | 乌托邦 **最低生活补贴**；**不做** 馆驿卒派单 |

---

## 六、明确不做

骑手、配送、招贤、应聘、雇玩家、律师、作家、trace 留痕、中介、委托做某事、叙事产出。

---

## 七、检查清单

- [ ] 新功能是否只是 **决策 + 数字**？  
- [ ] 市民钱是否有 **工资或补贴** 来源？  
- [ ] 职业是否绑 **机构 slot**？  
- [ ] 无玩家时城市能否 **cron 自转**？
