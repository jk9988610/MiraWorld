# 距离、配送与送达时间：划区还是纯文字？

> 状态：地图距离 + 外卖履约  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

> ⚠️ **2026-09-13 起本文不作为 v1.0 规范。**  
> 米拉世界采用 **直购直收**：下单 → 通知 → 背包，**无骑手、无配送子单、无 ETA**。  
> 现行约束见 **[35-简化原则定稿](./35-简化原则定稿.md)**。

## 一、问题

外卖员把饭送到家里：

- **距离**在游戏里怎么表示？  
- 要不要 **地址划分 / 区域派单**？  
- **多久能送到**？  
- 是做 **系统算路程**，还是只做 **文本描述**？

---

## 二、结论先说（尽量简单）

| 层 | 用什么 | 例子 |
|----|--------|------|
| **L2 硬逻辑** | **地点节点图**上的 **跳数 / 边权重** | 店在潮灯港，家在旧栈桥 → 距离 = 2 跳 |
| **L2 派单** | **粗区域标签**（不是真实街道） | `region_harbor` 的骑手优先看本区单 |
| **L2 时效** | **公式算预计送达窗** | 「约 2～4 小时」或「明日午后」 |
| **L3 叙事** | **文字描写路程** | 「渡口的雾比往常厚，脚夫绕了远路」 |

**不做：** GPS、真实经纬度、精细到门牌号的行政区划、骑手实时走位地图。

**口诀：距离认 **地点图**；地址认 **节点 + 家门牌**；时间认 **跳数公式**；好听话认 **文案**。**

---

## 三、和现有地图的关系（`03`）

世界地图已是 **节点 + 链接**，不是 2D 大地图：

```
        [ 潮灯港 ]
           /    \
    [ 旧栈桥 ]   [ 商会街 ]
```

| 概念 | 定义 |
|------|------|
| **节点** | `location_id`（官方地点或家园入口节点） |
| **边** | 两地点可通行的一条路 |
| **距离** | 两节点间 **最短路径** 的边权之和（或跳数） |

**家园地址** 不是「XX 路 88 号」，而是：

```
delivery_address =
  location_id: location_old_pier    # 地图上的入口节点（家在哪一片）
  home_id: home_8842                # 具体谁家
  display_name: 「雾边小筑」         # 门牌文字（L3）
```

顾客下单选 **送到哪个家** = 选已绑定的 `home_id`；系统已知它挂在哪个 `location_id` 下。

## 四、要不要「地址划分」？

### 4.1 推荐：**粗区域，不细街道**

| 方案 | 做法 | MVP |
|------|------|-----|
| **A. 纯文字** | 只写「送到雾边小筑」 | 太软，无法算运费和派单 |
| **B. 精细区划** | 街道、网格、邮编 | 太复杂，文字游戏不值 |
| **C. 粗区域标签** ✅ | 每个 `location_id` 挂 1～2 个 `region_id` | **推荐** |

示例区域（少而稳）：

| region_id | 包含节点示例 |
|-----------|--------------|
| `region_harbor` | 潮灯港、商会街 |
| `region_pier` | 旧栈桥、渡口 |
| `region_lake` | 镜湖驿、湖畔径 |

**派单规则（简单）：**

```
配送单可见性 =
  ① 骑手注册服务区域 ∩ 订单区域 非空
  或 ② 骑手当前「打卡所在」location 与店铺/收货点同 region
  或 ③ 超时后溢出到全服骑手池
```

不需要「3 公里内」——用 **同区优先、跨区加价、远区溢出**。

### 4.2 店铺与家的「地址」字段（MVP）

| 实体 | 系统字段 | 玩家看见 |
|------|----------|----------|
| 店铺 | `shop.location_id` + `stall_id`? | 「少盐食堂 · 潮灯港」 |
| 家园 | `home.anchor_location_id` | 「雾桥阿青的 · 雾边小筑 · 旧栈桥」 |
| 下单 | `delivery.home_id` 或 `delivery.location_id`（堂食） | 下拉选「我家」或「就在店里吃」 |

**不收集：** 省市区街道门牌、手机号（除非后期实名）。

## 五、距离怎么算？

### 5.1 图距离（L2）

每条边可有 **权重** `edge_weight`（默认 1）：

```
distance(shop, home) =
  shortest_path(shop.location_id, home.anchor_location_id)
  → 返回 hop_count 或 sum(edge_weight)
```

| 边类型 | 权重示例 | 叙事 |
|--------|----------|------|
| 平地街巷 | 1 | 寻常路程 |
| 雾桥 | 2 | 「桥常迷路」 |
| 战时封路 | ∞ 或绕行 +3 | 世界季 flag（`12`） |

**运费加成（可选）：**

```
delivery_fee = base_fee + per_hop × distance_hops
```

下单时顾客看见：**「配送 3 灯油（跨 2 区）」** — 可验证，不靠嘴说。

### 5.2 文字距离（L3）

订单状态页可加一句 **不用于计费** 的描写：

> 「脚夫说今日雾大，从港到栈桥会比平时久一点。」

与 `13` 一致：**钱和派单看 L2；气氛看 L3。**

## 六、多久能送到？（异步，不实时跟踪）

本作 **异步优先**（`04`）：骑手不必在线走路，顾客也不盯着地图看小点移动。

### 6.1 预计送达窗（ETA window）

```
eta_min = cook_time + base_delivery + hops × per_hop_min
eta_max = eta_min + async_buffer

展示给用户：
  「预计 今日 18:00–20:00 送达」
  或「约 2～4 小时后」（用游戏内钟或真实时间，待定）
```

| 变量 | MVP 建议 |
|------|----------|
| `cook_time` | 厨师出餐后才开始计配送；或固定 30min |
| `base_delivery` | 30min |
| `per_hop_min` | 每跳 20min |
| `async_buffer` | +60min（给错时上线留余地） |

**关键：** 这是 **承诺窗口**，不是秒级仿真。骑手点「取餐」「送达」推进状态机，**不必**模拟在路上走了多久。

### 6.2 订单配送状态（顾客看见）

```
待出餐 → 已出餐待取 → 运送中 → 已送达（待确认）→ 完成
```

| 状态 | 文案示例 |
|------|----------|
| 运送中 | 「潮灯信使已取餐，往旧栈桥去。」 |
| 已送达 | 「餐放在门口。请确认收餐。」→ 邮箱通知 |

**不做：** 骑手实时坐标、每 30 秒刷新位置（`05` 也不建议狂轮询）。

### 6.3 超时与托底

| 情况 | 处理 |
|------|------|
| 过久无人接配送单 | 溢出全服池 → 馆驿卒托底（`17`） |
| 超过 eta_max 未送达 | 顾客可申请查询；系统可自动完成或退款规则 |
| 骑手离线 | **允许** — 取餐时在线即可，送达可异步点完成 |

## 七、派给哪个骑手？（区域匹配）

```
配送子单生成（商家出餐后）
    │
    ▼
计算 route_region = shop.region ∪ home.region
    │
    ▼
池 A：注册服务区域 ∩ route_region 的骑手 + 本店雇佣骑手
    │
    ▼
池 A 无人接 → 池 B：同 map 邻接 region 的骑手
    │
    ▼
池 B 仍无人 → 池 C：全服骑手（运费可上浮）
    │
    ▼
仍无人 → 馆驿卒（系统托底，加价）
```

**骑手侧注册（轻量）：**

- 考证得「注册骑手」  
- 勾选 **常跑区域**（多选 `region_id`）  
- 可选：**当前打卡地点** 作为临时优先（`03` 已有）

**不需要：** 骑手住在哪、真实 GPS。

## 八、端到端：一碗面送到家

```
① 顾客在少盐食堂点「雾港汤面」+ 送到「雾边小筑」
      系统算：
        shop = 潮灯港 (region_harbor)
        home = 旧栈桥 (region_pier)
        hops = 2
        餐费 12 + 配送 4 灯油 → 托管 16

② 厨师出餐 → 配送子单进「旧栈桥 /  pier 区」池

③ 骑手小王（注册 region_harbor + region_pier）看见单 → 接单
      → 状态「运送中」
      → 文案：「从潮灯港出发，过商会街，往旧栈桥。」

④ 小王（可能几小时后上线）点「送达」
      → 顾客邮箱：「餐已至雾边小筑门口」
      → 顾客确认 → 分账（含配送费 4）

⑤ 全程距离靠 **2 跳** 算运费；叙事可多一句雾大（L3）
```

**堂食：** `delivery.location_id = shop`，hops = 0，无配送费。

## 九、和「纯文本描述」怎么分工？

| 只做文本 | 问题 |
|----------|------|
| 「很远，所以要 5 灯油」 | 店主随口要价，纠纷无法裁（`09`） |
| 「大概一会儿到」 | 顾客无法规划，体验虚 |

| 推荐组合 | 作用 |
|----------|------|
| **节点图 + 区域标签** | 运费、派单、ETA 公式 |
| **home display_name** | 「送到雾边小筑」— 人话地址 |
| **状态机 + 短文案** | 运送中、已送达 |
| **可选 L3 一句** | 氛围，不改 L2 到账 |

## 十、MVP 建议

| 做 | 不做 |
|----|------|
| 地点图边权 = 距离 | 经纬度、真实地图 |
| 3～5 个 `region_id` | 街道级区划 |
| 家园绑 `anchor_location_id` | 门牌号系统 |
| 运费 = base + hops | 动态竞价运费 |
| ETA 窗口文字 | 实时骑手追踪 |
| 同区骑手优先池 | 强制骑手只能接本区 |

## 十二、小结

| 问题 | 答案 |
|------|------|
| 距离怎么刻画？ | **地点节点图的最短路径**（跳数/边权） |
| 要地址划分吗？ | **要，但只做粗 region 标签**；不要精细街道 |
| 家地址是什么？ | **地图节点 + home_id + 屋名** |
| 多久送到？ | **公式算 ETA 窗口**；异步状态推进，不实时走位 |
| 派哪个骑手？ | **区域匹配优先 → 邻区 → 全服 → 馆驿卒** |
| 纯文本够吗？ | **不够**（计费派单要 L2）；文本负责 **门牌名和氛围** |

> 馆里认路，不认门牌号：  
> 从潮灯港到旧栈桥，图上两跳；  
> 脚夫跑哪片区的单，看区域标签；  
> 什么时候到，给你一个窗，不必盯着他每一步。
