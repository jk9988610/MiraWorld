# 结账与做菜流程：货币、工资、邮箱（尽量简单）

> 状态：经济 MVP + 厨师履约 + 账户简化  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  
> **定稿：** 四象见 [32](./32-四象统一定稿.md)；地 [31]；钱 [30]；**玩家按钮见 [36](./36-玩家操作与用语定稿.md)**；**v1.0 直购直收见 [35](./35-简化原则定稿.md)**。托管分账 = `order` + `ledger` record。下文旧「灯油」= **点**；旧「信箱」= 玩家 UI **通知**。

---

## 一、设计立场：先简单，不重复

| 原则 | 说明 |
|------|------|
| **一种主货币** | **信用点（credits / 点）**；库内 `wallet_credits`；不做炒汇 |
| **一个钱包** | 每人一个 **点数余额**；不登记银行卡 |
| **一种通知地址** | 用 **行者名（用户名）** 收系统/往来消息；不另建邮箱系统 |
| **工资先按单分** | MVP 员工 **每单分成** 进钱包；月薪自动发 v2 再说 |

**口诀：点数走托管；做完再分；钱进钱包；消息找行者名。**

## 二、货币是什么？有没有汇率？

### 2.1 主货币：信用点（点）

| 项 | 说明 |
|----|------|
| **名称** | **信用点**；UI 简称 **点** |
| **存哪** | 用户表 `wallet_credits`（**整数**） |
| **怎么得** | 完成单、系统奖励、通知领取、交易收入 |
| **怎么花** | 点菜、点挂单、开店费、发悬赏、订制 |
| **现实** | **不能提现**；不与人民币挂钩 |

### 2.1.1 信用点 vs 罐装灯油（物）

**定夺：钱是账上的点；灯油是场景里的气味/物品，不当钱。**

| 层 | 是什么 | 玩家界面 | MVP |
|----|--------|----------|-----|
| **L2 钱包** | **馆规记账单位**（信用点） | 「余额 88 点」 | ✅ 点菜、工资、分账都用它 |
| **L1 物品灯油** | **可持有的一罐/一盏油**（`item_lamp_oil`） | 背包里「灯油 ×3」 | ❌ v1.0 不做；v1.3+ 家园点灯用 |

**大白话：**

- 钱包里的 **点 = 钱**，馆里统一记账单位。  
- 背包里的 **灯油 = 物**，以后可以摆灯、熬汤、剧情消耗——**和 `wallet_credits` 不是一回事**。

世界观上：平台统一记 credits；叙事用「点」和区号，**付钱只动 `wallet_credits`**。

| 玩家问 | 系统答 |
|--------|--------|
| 我钱包 12 点能点面吗？ | 看余额，够就扣 `wallet_credits` |
| 我背包有灯油能点面吗？ | **v1.0 不能** |
| 我能自己点灯照明吗？ | **v1.0 无**；以后家园 `fixture` 消耗 `item_lamp_oil` |

**帮助页一句：**  
> **信用点（点）** 是馆里通用钱；罐装灯油（若以后有）是另一类物品，别混在余额里数。

### 2.2 MVP：**不做汇率**

| 不做 | 理由 |
|------|------|
| 多币种（金/银、金币/银币） | 玩家要记换算，纠纷多 |
| 势力间汇率 | 像现实外汇，复杂且易套利 |
| 点 ↔ 人民币 | 涉合规，MVP 不做 |

**后期若要「势力票券」**：当作 **优惠券 / 活动道具**，不是第二货币；仍用 **点** 结账，券只抵一部分。

### 2.3 店铺也有钱包（可选子账户）

```
玩家个人钱包 wallet_credits
店铺司库 shop_wallet（绑 shop_id，店主可提现到个人钱包）
```

MVP 可合并：**小店直接用店主个人钱包**；店大了再拆 `shop_wallet`（`11` 司库）。

## 三、怎么结账？（托管 → 完成 → 分账）

和现实外卖一样：**先付钱到柜台（系统托管），做完了再分**。

```
顾客下单「雾港汤面 · 12 灯油」
    │
    ▼
系统检查顾客 wallet_balance ≥ 12
    → 是：扣 12，记入订单 escrow（托管池）
    → 否：提示灯油不足
    │
    ▼
厨师做菜、订单完成、顾客确认（或超时自动确认）
    │
    ▼
系统按 ledger 分账（示例）：
    · 店主   7 灯油
    · 厨师   3 灯油  ← 员工工资（若本单由雇员做）
    · 平台   2 灯油
    │
    ▼
各方 wallet_balance 增加；顾客背包 +1 面（或已食用标记）
```

| 概念 | 大白话 |
|------|--------|
| **escrow / 托管** | 钱暂时锁在订单里，谁都没拿走 |
| **ledger / 分账流水** | 完成后系统记账：谁该得几灯油 |
| **不需要银行卡** | 全是馆内虚拟数字 |

顾客下单时看见 **总价明细**（`01` §3.5.6），避免扯皮。

## 四、录用了厨师，他怎么做一碗面？

以 **「少盐食堂」雇用的注册厨师** 接店内单为例。

### 4.1 参与角色

| 角色 | 做什么 |
|------|--------|
| **顾客 A** | 在店铺点挂单「雾港汤面」 |
| **店主** | 开店、备库存、定分成比例、可自己做菜 |
| **厨师 B**（雇员） | 接本店烹饪子单、消耗材料、出餐 |
| **系统** | 托管、验材料、扣库存、产出物品、分账 |

### 4.2 一步一步（完整店流程 · 参考）

> **v1.0 陈师傅 MVP（见 35）：** 顾客点面 → 通知 → **确认收进背包** → stack +1；**无骑手、无配送子单**。下列含库存/雇员，供 v1.2+ 参考。

```
① 顾客在店铺页点「雾港汤面 · 12 点」
      → 12 点进托管

② 订单进「少盐食堂」队列
      → 店主 或 已授权厨师 可见

③ 厨师 B 点「接单 / 开始烹饪」
      → 系统读配方 recipe_noodle_mist：
           需要 shop 库存或后厨背包：
             item_fog_wheat ×2
             item_tidelamp_soy ×1
      → 不足：订单挂起，**通知**店主补货（`16` `18`）

④ 材料足够 → 厨师点「出餐」
      → 系统 L2 硬操作：
           扣材料
           产出 item_noodle_bowl ×1（crafted_by: 厨师B）
           订单状态 → ready（待收进背包）

⑤ 交付
      · **v1.0：** 通知 → 顾客点 **确认收进背包** → stack +1
      · 堂食（v1.2+）：顾客在店页 **确认收进背包**
      · ~~外卖骑手~~（**已取消**，见 **35**）

⑥ 顾客确认收餐（或 24h 自动确认）
      → 托管 12 点按店规拆分：
           店主 7 + 厨师 3 + 平台 2
      → 厨师 B 的 wallet_balance +3

⑦ 可选 L3：厨师附一句上菜台词进交付**通知**
      「面汤用昨夜的雾，你信也好不信也好。」
```

### 4.3 和 `13` 的关系

| 硬（L2） | 软（L3） |
|----------|----------|
| 真的扣了面粉酱油 | 厨师说「美国进口」——好听而已 |
| 真的产出 `item_noodle_bowl` | 上菜台词 |
| 真的分 3 点给厨师 | — |

### 4.4 店主自己做菜

若店里 **没有雇员在线**，店主自己接③④步；分账里「厨师份」归店主或省略，规则在开店时写死。

## 五、工资怎么发给员工？

### 5.1 MVP：**只做「每单分成」**

| 项 | 说明 |
|----|------|
| **何时发** | **订单完成且分账时** — 即时进员工 `wallet_balance` |
| **发什么** | **点**（不是现实工资） |
| **谁定比例** | 招聘帖或录用时约定（`21`）：如「每单 3 点」或「销售额 25%」 |
| **要不要银行卡** | **不要**；全是馆内钱包 |

```
订单完成
    → ledger 写一行：user_id=厨师B, amount=3, reason=order_split
    → 厨师 B wallet_balance += 3
    → 系统**通知**：「本单分得 3 点，已入账。」（可手动领提示，钱其实已到账）
```

### 5.2 月薪（v2，MVP 不做）

「月薪 80 点」需要 **定时任务** 每月从 `shop_wallet` 扣款 → 易忘发、易纠纷。  
**MVP 建议：** 招聘帖只写 **按单分成**；月薪等店稳定了再加。

### 5.3 试工钱

试工单同样：**托管 → 完成 → 进应聘者钱包**（`21`）。

## 六、账户与通知：尽量简单

> 玩家底栏叫 **通知**；实现表名仍可用 `messages` / `mail_messages`。

### 6.1 注册与登录（建议简化）

| 现在代码 | 建议演进（游戏向） |
|----------|------------------|
| email + 密码注册 | **行者名（username）+ 密码** 即可玩 |
| email 唯一 | 行者名唯一；email **可选**（找回密码用） |

**玩家记得一个名字就行**，不必记两套「登录邮箱」和「游戏邮箱」。

### 6.2 往来通知地址 = 行者名

**不另建邮箱服务器。** 游戏内发消息（玩家 UI：**通知**）：

```
收件人：雾桥阿青
（内部即 user_id，显示用行者名）
```

不必 `a@b.com`。若 UI 要好看，可显示为：

```
雾桥阿青 @ 馆
```

仅是 **显示格式**，背后还是 `user_id`。

| 通知类型 | 地址 | 内容 |
|------|------|------|
| **系统通知** | （无地址，系统发） | 奖励、结案、执照、面好了 |
| **往来通知** | 对方 **行者名** | 玩家私信、订单沟通 |
| **店铺留言** | 店铺 **display_name** 或 shop_id 短码 | 顾客给店留言 |

### 6.3 和登录 email 的关系

| 字段 | 用途 |
|------|------|
| `username` / 行者名 | 登录、游戏内收**通知**、名片显示 |
| `email`（可选） | 仅账号安全：找回密码、重要通知（可关） |
| `display_name` | 昵称，可与行者名相同；MVP 可 **行者名 = 显示名** 减少字段 |

**减少重复：** MVP 只强制 **一个名字**；不要「用户名 + 昵称 + 邮箱名」三套。

### 6.4 虚拟银行卡？

**不需要。**

| 现实 | 平台 |
|------|------|
| 银行卡 | **点钱包** `wallet_credits` |
| 支付宝 | 同上 |
| 提现 | MVP **不做** |

所有收入支出只在 **点 + 背包物品** 两条账上。

## 七、数据模型草图（实现参考）

```text
users
  id, username UNIQUE, password_hash
  email NULLABLE          -- 可选
  wallet_credits          -- 信用点 credits（整数）
  display_name            -- MVP 可 = username

shops
  shop_id, owner_id, shop_wallet NULL  -- MVP 可省略

shop_employees
  shop_id, user_id, role_id, pay_rule  -- 如 per_order: 3 或 pct: 0.25

orders
  order_id, buyer_id, shop_id, offer_id, total_credits
  escrow_amount, status, assigned_chef_id

ledger_entries
  id, order_id, user_id, amount, type  -- split_owner | split_chef | platform_fee

recipes
  recipe_id, inputs[], output_item_id

-- 游戏「通知」不是 SMTP，是表：
messages
  id, to_user_id, from_user_id|system, thread_id, body, read_at
```

## 八、端到端例子（一碗面 + 工资）

```
1. 雾桥阿青（顾客）wallet 有 50 点
2. 进少盐食堂，点雾港汤面 12 点 → 托管 12，剩 38
3. 厨师小李（雇员）接单 → 店库存扣面材 → 出餐
4. 雾桥阿青 **确认收进背包** → stack +1 面
5. 分账：店主 +7，小李 +3，平台 +2
6. 小李 wallet 看见多 3 点；系统通知：「本单 3 点已入账」
7. 小李给阿青往来消息（可选）：「少盐照旧，慢用。」
   收件人填：雾桥阿青
```

全程：**无汇率、无银行卡、无第二邮箱名。**

## 九、MVP 清单

| 做 | 不做 |
|----|------|
| 单一货币信用点 | 多币种、汇率 |
| 订单托管 + 完成分账 | 玩家私下转账 |
| 厨师：接单 → 扣料 → 出餐 → 分工资 | 复杂烹饪小游戏 |
| 员工工资：**按单进钱包** | 月薪、银行卡 |
| 通知：**行者名收件** | 独立邮箱注册 |
| 行者名登录 | 强制绑定真实邮箱 |

## 十一、小结

| 问题 | 答案 |
|------|------|
| 厨师怎么做面？ | **接单 → 验配方扣库存 → 出餐 → 顾客确认收进背包 → 分账** |
| 货币是什么？ | **信用点（点）**；馆内虚拟钱 |
| 怎么结账？ | **下单托管 → 完成 ledger 分账 → 进各方钱包** |
| 有汇率吗？ | **MVP 没有** |
| 工资怎么发？ | **按单分成，点即时进员工钱包** |
| 要银行卡吗？ | **不要** |
| 通知？ | **往来消息找行者名**；登录 email 可选 |

> 点一碗面，十五点先搁在柜上；  
> 面出锅，钱按单分开——厨师那份，直接进他馆里的点数袋。  
> 不必换汇，不必报卡号；想找他，写信给行者名就行。
