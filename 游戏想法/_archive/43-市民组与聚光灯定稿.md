## 一、市民组（PopGroup）

| 项 | 定稿 |
|----|------|
| 规模 | **1000 人 / 组** |
| 首发 | 潮灯市 **10 组**（1 万人），初始化固定，不日刷 |
| 雇佣 | **一组一主雇机构** + 一个 `job_type` |
| 钱包 | `wallet`：**仅** 工资 + 无岗时 **最低生活补贴** |
| 消费 | 日 tick 内按 `wallet` 与 `pref` 买可见 `offer` |
| 标签 | 配置层 `segment=citizen`；**不对玩家展示** segment |

### 字段（建议）

```
pop_group: id, city, headcount=1000, wallet,
           primary_institution_id, job_type,
           pref_json, updated_at
```

### 偏好默认 `pref_json`

```json
{ "food": 0.45, "consumable": 0.25, "material": 0.15, "tool": 0.10, "other": 0.05 }
```

按 item `tags` 加权选品类；首发 **无旅客** segment。

## 二、钱从哪来（禁止无中生有）

| 状态 | 收入来源 |
|------|----------|
| **在岗** | 主雇机构 **工资**（≥ 最低工资，见 `44`） |
| **无岗** | 城市 **最低生活补贴**（`min_living_subsidy × headcount`） |

**禁止：** 每日向全体市民注入「消费力常数」。  
补贴由 **城市福利基金** 支出（乌托邦定额注入该 fund，见 `44` §三）。

## 三、购买与 order

- `buyer_kind = pop_group`  
- 卖家：NPC 机构或玩家店  
- 履约：现有 `order` + NPC `auto_on`  
- 组内 `wallet` 不足则停止购买

## 四、聚光灯（Spotlight）— 看起来像实例

| 项 | 定稿 |
|----|------|
| 条数 | **每店 10 条**，FIFO |
| 性质 | **仅展示**；删了不影响 ledger |
| 触发 | 该店有一笔 `pop_group` 订单 ** settled** |
| 命名 | **姓 + 职业显示名**（职业必须真实） |

### 姓氏池

从 **常见单姓** 与 **常见复姓** 随机（默认权重 **单姓 70% / 复姓 30%**）：

- 单姓：王、李、张、刘、陈、杨、黄、赵、周、吴…  
- 复姓：欧阳、司马、诸葛、上官、东方、皇甫…  

### 职业名

**不得随机。** 必须等于该买家组 **`job_type` 的显示名**（如 医生、铁匠、厨师），且该组 **本 tick 有岗、机构存在对应 slot**。

示例：`王医生`、`欧阳铁匠`、`李厨师`。

### 配置示例 `names/pop_spotlight.json`

```json
{
  "single_surnames": ["王","李","张","刘","陈","杨","黄","赵","周","吴","徐","孙","马","朱","胡","郭","何","林","罗","高"],
  "compound_surnames": ["欧阳","司马","诸葛","上官","东方","皇甫","尉迟","公孙","慕容","司徒"],
  "surname_weights": { "single": 0.7, "compound": 0.3 }
}
```

## 五、日 tick 中的顺序（市民相关）

```
① institution_production
② institution_payroll          → 在岗组 wallet
③ city_welfare_subsidy       → 无岗组 wallet（最低生活补贴）
④ pop_purchase               → orders
⑤ fulfill + ledger
⑥ spotlight_sample             → 每店 ≤10
```

## 六、API（规划）

- `GET /shop/{id}/spotlight` → `{ items: [...] }` 最多 10 条  

---

## 七、验收

1. 无岗组只有补贴，消费力低于在岗组。  
2. 无机构支撑的「医生」名 **不会** 出现在 Spotlight。  
3. 每店 Spotlight ≤10，姓为单姓或复姓。  
4. 关店 / 缺货 → 市民购买减少（可观测）。
