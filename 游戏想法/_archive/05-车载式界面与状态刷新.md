# 车载式界面与状态刷新

> 状态：UI 壳层 + 数据刷新 · **v1.0 壳层以 [36](./36-玩家操作与用语定稿.md) 为准**  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、一句话

**没有固定首页——用户走到哪，哪就是首页。**  
界面像**车里**：挂饰（地图、通知、背包、我的）始终跟着你；**风景**（地点、故事、菜单）随你移动而换。  
世界是异步的，状态变化往往**迟迟才来**；不盲目狂轮询，而是**看用户在哪、在不在看、需要什么**再决定是否刷新。

---

## 二、车载隐喻：壳层 + 风景

### 2.1 两层结构

```
┌─────────────────────────────────────────────────────┐
│  车载壳层（Shell）— 跟着玩家走，不随地点消失          │
│  [ 地图 ] [ 通知● ] [ 背包 ] [ 我的 ] …               │
├─────────────────────────────────────────────────────┤
│                                                     │
│           风景层（Viewport）— 随「所在页」变化        │
│                                                     │
│     旧栈桥 · 潮灯港          /    悬赏栏列表         │
│     叙事正文、地点链接…          /    订单、痕迹…     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

| 层 | 类比 | 内容 | 行为 |
|----|------|------|------|
| **壳层** | 车里挂饰、仪表盘 | 全局导航、未读角标、账号、快捷入口 | **固定附着**，任何页面都在 |
| **风景层** | 窗外景色 | 当前地点、文档页、悬赏列表、店铺 | **随路由/地点 ID 替换** |

玩家没有「先回首页再出发」——**他已经在车里了**，只是窗外换了一条街。

### 2.2 和「无首页」的关系

| 传统站点 | 本作 |
|----------|------|
| 首页 = 门户、汇总入口 | **无单独门户**（或门户只是众多风景之一） |
| 内页 = 二级，缺全局入口 | **任意页都带完整壳层** |
| 从子页回首页找功能 | 功能始终在壳层上 |

与 [03-地图打卡与异步痕迹](./03-地图打卡与异步痕迹.md) 衔接：地图移动 = 风景切换；打卡变色可在进入地图风景或回到壳层地图入口时刷新。

与 [02-点菜式成长](./02-点菜式成长.md) 衔接：v1.0 **无「我要」页**；点菜从地图进 NPC 菜单（如陈师傅）。

与 [36-玩家操作与用语定稿](./36-玩家操作与用语定稿.md) 衔接：底栏 **地图 · 通知 · 背包 · 我的**。

## 三、状态是「迟迟的」：要不要轮询？

异步世界里，很多变化**不会秒到**：

- 对方回信、订单状态变更、通知未读、地点新痕迹……

页面需要**偶尔**与服务器对齐，但：

> **不等于** 全站每 3 秒轮询一遍。

### 3.1 原则：按需刷新，不是盲目轮询

| 策略 | 说明 |
|------|------|
| **进入时拉一次** | 打开通知 / 订单 / 地点页 → 立即 `GET` 最新状态 |
| **用户操作时写** | 发信、接单、领取奖励 → `POST` 后本地乐观 UI，等服务器确认 |
| **条件轮询** | 仅当「用户正在看、且该页需要新鲜度」时定时拉 |
| **可见才轮询** | 浏览器标签页隐藏 → **暂停**（Page Visibility API） |
| **空闲降频** | 长时间无操作 → 拉长间隔或停轮询 |
| **离开即停** | 路由切走 → 取消该页的 timer / abort fetch |

### 3.2 什么页面需要轮询、什么不需要

| 风景 / 页面 | 新鲜度需求 | 建议 |
|-------------|------------|------|
| 纯 lore 文档（设定百科） | 低 | **不轮询**；静态构建或 CDN |
| 地点叙事（03 风景） | 低～中 | 进入时拉痕迹列表；停留时可 **慢轮询**（如 60～120s）或手动刷新 |
| 系统 **通知** | 中 | 打开列表时拉；壳层未读角标 **慢轮询**（如 30～60s），仅标签页可见 |
| 订单详情 / 进行中商单 | 中～高 | 页内时 **中等频率**（如 15～30s）；完成后停止 |
| 悬赏栏列表 | 中 | 进入列表拉一次；可选 30s 刷新，或「下拉刷新」 |
| 壳层未读汇总 | 低～中 | 一条轻量 `/api/messages/summary` 慢轮询即可，不必每页各拉 |

**默认倾向：少轮询、慢轮询；用户下拉或点刷新按钮永远可用。**

### 3.3 根据「使用情况」决定是否轮询

可用简单信号（无需复杂 AI）：

```
是否轮询？
  ├─ 标签页是否 visible？ ─ 否 → 停
  ├─ 用户是否 idle（如 5min 无操作）？ ─ 是 → 停或 5min 一次
  ├─ 当前路由是否需要新鲜数据？ ─ 否 → 停
  ├─ 是否有 in_progress 订单？ ─ 是 → 该页加快
  └─ 否则 → 壳层 summary 慢轮询
```

实现上：一个全局 `usePolling` / `useShellState` composable，集中管理 interval 与 abort，避免每个组件各自 `setInterval` 打爆服务器。

### 3.4 和 WebSocket 的边界

| | 轮询（默认） | WebSocket（可选后期） |
|--|--------------|------------------------|
| 复杂度 | 低 | 高（连接、重连、扩容） |
| 异步通知 | 足够 | 非必须 |
| 订单状态 | 中等频率轮询够用 | 可做，但 MVP 不必 |
| 全服聊天 | 不做 | 不做 |

与 [04-异步通知与往来](./04-异步通知与往来.md) 一致：**不为一条通知维持长连接**；未读角标慢轮询 + 打开通知页全量拉取即可。

## 四、壳层挂件：跟着玩家走什么

建议固定在壳层、任意风景可见的入口（首批）：

| 挂件 | 作用 | 状态刷新 |
|------|------|----------|
| **地图** | 潮灯市、打卡、进 NPC | 路由变即更新 |
| **通知** | 系统 message（v1.0） | 未读数：summary 慢轮询 |
| **背包** | stack 持有物 | 确认收进背包 / 食用后刷新 |
| **我的** | handle、余额、打卡 | 登录后拉一次 |

**v1.0 不做：** 壳层「我要」、往来私信、悬赏栏角标。

角标规则：

- **有未读通知** → 壳层小红点；**不弹窗**（零推送）
- 玩家点进通知 → 该页全量拉取，壳层角标更新

### 4.1 风景层随路由变化

```text
/miraworld/play/messages.html   → 风景：通知列表
/miraworld/play/stacks.html     → 风景：背包
/miraworld/play/city.html       → 风景：潮灯市地图
```

VitePress 现有 `Layout.vue` 可演进为：**壳层组件常驻 + 默认 slot 为风景**。文档页与未来游戏页共用同一辆车。

## 五、对服务器与流量的影响

| 做法 | 影响 |
|------|------|
| 每页 3s 全量轮询 | 日活上千就浪费；**避免** |
| 仅 summary + 可见页条件轮询 | 可控；适合小团队单库 |
| 进入页时拉一次 | 最省；多数 lore 页仅此即可 |
| 标签页 hidden 暂停 | 移动端/多标签必备 |

单用户粗算（壳层 60s summary + 订单页 30s）：每小时约 **几十次** 轻量请求，可接受。  
比维持 WebSocket 心跳更省运维心智。

## 六、MVP 可验证什么

1. **Layout 壳层**：游戏页显示 **地图 · 通知 · 背包 · 我的**  
2. **无独立首页**：deep link 进陈师傅/订单，壳层仍完整  
3. **`useShellState`**：仅标签页 visible 时 60s 拉未读 summary  
4. 进入通知页 → 全量拉 message + 停止重复轮询  
5. 纯 lore 页 → 零轮询  
6. 问玩家：是否感觉「功能一直在手边」，而不是总要回首页？

## 八、小结

| 维度 | 选择 |
|------|------|
| 首页 | **无固定首页**；所在页即首页 |
| UI | **车载壳层** + **可变风景** |
| 状态 | 异步、迟迟到达 |
| 刷新 | **按需 + 条件轮询**；visible / idle / 路由感知；不盲目狂刷 |
| 实时 | MVP **不依赖 WebSocket** |

> 你在车里，挂饰一直在；窗外从港口的雾变成栈桥的雨。服务器不必每秒敲窗告诉你「雨还在下」——只有你望着窗外时，偶尔抬头看一眼就够了。
