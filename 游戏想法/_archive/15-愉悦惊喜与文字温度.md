# 愉悦、惊喜与文字温度

> 状态：体验设计 + 文案原则  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、一句话

很多现实中的愉悦 **不必真的发生**，只要在文字里 **被记得、被接住、被轻轻超预期**——  
MiraWorld 是文本游戏，优势不是画面，是 **叙述的温度、异步的惊喜、馆规里的小小偏袒**。

---

## 二、现实中「说一说就愉悦」的事（可搬到线上）

| 现实里口头一说就开心 | 为什么有效 | 线上对应 |
|---------------------|------------|----------|
| 「你还记得我喜欢少盐」 | **被记得** | 订单忌口被厨师回信引用 |
| 「多送了你一勺」 | **超预期** | 邮箱奖励比 SKU 多 1 次 / 小挂件 |
| 「今天请你喝汤，不算钱」 | **恩惠感** | 系统/势力节日免单券 |
| 「你是本月第一位来客」 | **稀缺 + 重视** | 地点首访粉笔、成就庆祝信 |
| 「上次那单做得真好」 | **被认可** | 完成后对方信箱一句谢（异步） |
| 「给你留了窗边位」 | **专属感** | 地图「你常来」链接暖色（已有打卡） |
| 「没想到吧」 | **惊喜** | 隐藏地点、无预告成就 |
| 「慢用，不赶」 | **不施压** | 无推送、无主线、帮助页语气 |
| 「这事挺逗的」 | **幽默共谋** | L3 台词撒谎、馆规不罚（`13`） |
| 「你选的这条路很少人走」 | **身份认同** | 口味谱反馈文案 |

**共性：** 被看见、被尊重、略超预期、不赶、有一点私人的味道。

## 三、超出预期：可以在哪些方面体现？

### 3.1 按系统模块

| 模块 | 愉悦 / 惊喜做法 | 超预期示例 |
|------|-----------------|------------|
| **系统邮箱** | 庆祝信、终战谢礼、节日电报 | 信末多一行「附：一盏未点的灯油」 |
| **手动领奖** | 点击领取瞬间的文案 | 「你收下了。汤还热。」（短，不刷屏） |
| **地图打卡** | 首次到访专属一句 | 非通用模板，按 `location_id` 写 |
| **痕迹** | 前人留的暖句、花、小旗 | 非垃圾广告；官方偶尔埋彩蛋痕迹 |
| **订单完成** | 厨师交付信比订单多一句 | 「多写了一段只有你能看到的脚注」 |
| **成就** | 庆祝 + 拓展岔口（`02`） | 解锁隐藏地图邻接（不预告） |
| **投票** | 局末战报有你的名字感 | 「港务营今夜多了一票迟来的声」 |
| **店铺** | 回购顾客 SKU 文案变 | 「欢迎回来，少盐照旧？」 |
| **帮助页** | 路牌语气暖，不班主任 | 「迷路不丢人，馆子很大。」 |
| **口味谱** | 周期小结像饮食日记 | 「你最近常点辣——厨房记住了。」 |
| **空状态** | 信箱空、悬赏空 | 不是「暂无数据」→「今日风静，无信。」 |

### 3.2 惊喜的类型（设计时可勾选）

| 类型 | 说明 | 频率 |
|------|------|------|
| **小恩惠** | 多一点点奖励、多一句谢 | 常 |
| **彩蛋** | 隐藏地点、稀有粉笔、冷笑话 | 稀 |
| **回调** | 文案引用你上次订单/打卡 | 中 |
| **节日仪式** | 全服同一主题一天 | 季 |
| **异步人情** | 陌生人给你留痕/回信 | 玩家驱动 |
| **馆规偏袒** | 退款顺利、申诉快结案 | 少，要真 |

**原则：** 惊喜 **宁少勿滥**；每次超预期都要 **对得起 L2**（真多给了、真解锁了），否则变空头支票（`13`）。

## 四、文本游戏应注重怎样的叙述？

### 4.1 文字温度的六个杠杆

| 杠杆 | 做法 | 避免 |
|------|------|------|
| **具体** | 「灯油在纸缘洇开一圈」 | 「获得了奖励」 |
| **短** | 一句画面 + 一句人情 | 三段设定集 |
| **记得你** | 用 `忌口`、`口味`、`上次地点` | 全员同一套台词 |
| **慢** | 句号、换行、留白 | 感叹号轰炸 |
| **诚实分层** | 硬的好消息走背包；软的走台词 | L3 承诺 L2 没有的 |
| **不赶** | 「何时来都行」 | 「限时否则失败」（除非战时季明确） |

### 4.2 语气：馆子里的温度，不是客服腔

| ✅ 可以 | ❌ 不要 |
|---------|---------|
| 「汤还热。慢用。」 | 「恭喜您完成 TASK-8842」 |
| 「你上次说少盐——记住了。」 | 「用户您好，您的订单已处理」 |
| 「今日风静，信箱无信。」 | 「当前列表为空」 |
| 「多一盏灯油，不算账上。」 | 「额外奖励 +10（系统发放）」 |

**人称：** 第二人称「你」可用，但 **少用「亲」「亲爱的玩家」**；像掌柜对熟客，不像微商。

### 4.3 叙事节奏（微结构）

```
【一句景象】 雾从栈桥缝里渗上来。
【一句人事】 厨房给你留了一格位子，没问你来不来。
【一句可选行动】  → 〔打开我要〕 〔继续走〕
```

即使是系统通知，也可 **景象 + 人情 + 行动**，不必只有 bullet list。

### 4.4 与「三层真相」的配合（`13`）

| 层 | 温度怎么用 |
|----|------------|
| **L3** | 随便浪漫、幽默、撒谎——愉悦的主要来源 |
| **L2** | 惊喜要真的：多一次、真解锁、真进邮箱待领 |
| **L1** | 百科条目也可写得有气味：`雾晶盐，潮灯港出，味薄而持久` |

**最暖的组合：** L3 写得美 + L2 真的多给了一点点。

## 五、举例：同一件事，冷与暖

**订单完成 — 冷：**
> 订单 #1024 已完成。奖励已发放。

**订单完成 — 暖：**
> 护送的那封信到了。收信人没露面，只在门缝里回了一声「收到了」。  
> 你的灯油多留了 5——对方硬塞的，系统只好记在账上。  
> 〔领取〕

**首次打卡 — 冷：**
> 地点已记录。

**首次打卡 — 暖：**
> 你第一次踏上旧栈桥。桥板记得很多人，但今天多一个你。  
> 链接的颜色会慢慢变——那是足迹，不是作业。

## 六、愉悦与现有设计原则不冲突

| 原则 | 愉悦怎么配合 |
|------|--------------|
| 无主线（`02`） | 惊喜是 **捡到**，不是 **催你捡** |
| 零推送 | 暖在 **打开信箱/地图时**，不弹窗 |
| 异步（`04`） | 迟来的回信、迟来的痕迹 = 温度 |
| 点菜 | 「少盐记住了」= 忌口被尊重 |
| 律师/馆规（`09`） | 胜诉结案信也可以写得体面，不羞辱败方 |
| 投票（`14`） | 胜方谢礼像「庆功宴分一碗汤」，不是氪金狂欢 |

## 七、设计方 / 创作者清单（落地用）

写任何玩家可见文案前，问四句：

1. **有没有一句只对这个玩家成立？**（回调）  
2. **有没有一点超出刚才的承诺？**（小恩惠）  
3. **有没有一个具体感官词？**（雾、灯、盐、风）  
4. **有没有给不赶时间的余地？**（慢用、何时来都行）  

官方内容（世界季、使馆电报、地点首访）优先做暖；  
玩家 UGC（粉笔、信箱）靠馆规筛垃圾，**不统一润色**。

## 八、MVP 可先做的 5 个「小愉悦」

| # | 做什么 | 成本 |
|---|--------|------|
| 1 | 每个地点 **首次打卡** 一句专属短文案 | 低（按 location 写） |
| 2 | 订单完成 **领取按钮** 旁一句变化谢辞 | 低 |
| 3 | 空信箱文案替换为世界观句子 | 极低 |
| 4 | 成就庆祝信用「景象+祝贺」，非纯表格 | 中（`02` 已有框架） |
| 5 | 偶尔 SKU 完成多 **+1 次** 不写进预告（稀有） | 低（馆规允许时） |

## 十、小结

| 问题 | 答案 |
|------|------|
| 什么让人愉悦？ | **被记得、被接住、略超预期、不赶、具体、有一点幽默** |
| 在哪体现？ | 邮箱、打卡、交付、空状态、成就、痕迹、投票谢礼、口味谱… |
| 文本怎么写？ | **短、具体、像掌柜不像客服**；L3 暖 + L2 真 |
| 与惊喜？ | 少而真；回调与隐藏优于天天送大礼 |

> 文字游戏的温度，不在辞藻堆砌，  
> 而在 **你还记得他少盐，而碗底真的多留了一口汤。**
