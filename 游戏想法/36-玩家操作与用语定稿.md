## 一、一句话

**玩家看见的动词要少、要稳：** 点单、确认收进背包、**食用**、**使用**、**放入背包**、打卡、读通知。  
同一动作全站同一个词；代码/API 用英文键，**不与玩家文案混用**。

---

## 二、物的两种位置（先分清再谈操作）

| 位置 | 四象 | 玩家怎么说 | 说明 |
|------|------|------------|------|
| **背包里** | `stack`（holder=玩家） | **背包** | 底栏「背包」页；`/stacks` |
| **背包外** | 场景/订单待领/地面（实现可不同） | **眼前 / 待领** | v1.0 主要是 **订单待确认**；v1.1+ 可有 spot 掉落 |

**规则：** 背包外 ≠ 已经在 stack 里。  
「放入背包」= 从背包外 → stack +1；「食用/使用」= 通常消耗 stack 或场景物，**不经过配送**。

## 三、标准操作（玩家文案 · 定稿）

### 3.1 四个通用动词

| 玩家文案 | 适用 | 效果（L2） | API 建议 | 禁用 |
|----------|------|------------|----------|------|
| **放入背包** | 任何可持有物（背包外） | stack +1 | `PUT_TO_STACK` / `stack.add` | 领取、收取、装进（口语偶尔可，文档不用） |
| **食用** | 食物类 `item` | stack -1（或场景物消失）+ 可选效果 | `CONSUME` | 对食物写「使用」 |
| **使用** | 工具类 `item` | 触发工具效果；是否 -1 看配置 | `USE` | 对工具写「食用」 |
| **确认收进背包** | 订单已 ready（待领） | order settled + stack +1 | `pickup`（实现名可保留） | **取餐**、送达、收货 |

### 3.2 按物品标签（`items.json` · `tags`）

| tags | 背包外按钮 | 背包内按钮 |
|------|------------|------------|
| `food`, `consumable` | **食用** · **放入背包** | **食用** |
| `tool` | **使用** · **放入背包** | **使用** |
| `material` | **放入背包** | （暂无，或 v1.2「用于制作」） |
| 仅 `food` 无 `consumable` | **放入背包** | （同上，是否可食用看配置） |

**原则：** 标签决定 **可用动词集合**；UI 只展示允许的按钮，不造第四第五个同义词。

### 3.3 订单路径（无背包外长期停留）

简化模型下，陈师傅的面 **默认**：下单 → 通知 → **确认收进背包**（一步进 stack）。  
若将来「面在眼前」场景：仍用 **放入背包**，与订单 **确认收进背包** 二选一实现，**玩家文案统一用「放入背包」或「确认收进背包」之一**，不在同屏混用。

| 场景 | 推荐玩家文案 |
|------|--------------|
| 订单页 / 通知跳转 | **确认收进背包** |
| spot 掉落、地上拾取 | **放入背包** |
| 已在背包的食物 | **食用** |
| 已在背包的工具 | **使用** |

### 3.4 委托路径（v1.5 · bounty）

| 玩家文案 | 适用 | API |
|----------|------|-----|
| **发委托** | 悬赏栏发购/售单、扣托管 | `POST /bounties`（`kind=buy\|sell`） |
| **接委托** | 接 open 单 | `POST /bounties/{id}/take` |
| **交差** | 接单人完成 | `POST /bounties/{id}/submit` |
| **确认交差** | 发单人放款 | `POST /bounties/{id}/settle` |
| **取消** | 仅 open 单退托管 | `POST /bounties/{id}/cancel` |

**限制：** 最多同时上架 **10 个**委托订单（购/售合计）。不支持「委托做某事」自由任务单。

与 **点面（order）** 分栏：陈师傅/玩家店 = 买物；悬赏栏 = 购售托管。

**通知：** 订单与委托 milestones **一律走通知**（已删除 `in_person` / 当面交差）。

## 四、名词与界面（玩家侧）

| 概念 | 玩家标准用语 | 代码/配置 | 废弃/勿混用 |
|------|--------------|-----------|-------------|
| 货币 | **点** | `wallet_credits`, `credits` | 灯油、银币、托管金（文档解释可用「扣点」） |
| 持有物列表 | **背包** | `stack`, `/stacks` | 库存、物品栏、inventory |
| 菜单一行 | **挂单**（帮助页）/ 口语 **点一碗** | `offer` | SKU、商品、SKU 行 |
| 物定义 | 显示名（一碗面） | `item`, `item_id` | 物品种类、道具 ID 对玩家 |
| 系统信息 | **通知** | `message`, `/messages` | 信箱、邮件、来信（底栏已定为「通知」） |
| 订单/委托进展 | **一律通知** | `message` + `ref_type` | ~~当面不发通知~~、`in_person` |
| 卖家菜单 | **点** / **点这一碗** | `POST /records/order` | 购买、下单（文档可用「下单」） |
| 探索 | **打卡** | `visit` | 签到、到点 |
| 底栏 | **地图 · 通知 · 背包 · 我的** | `/play/*` | 食堂、信箱 |

## 五、代码/API 与文档分工

| 层 | 语言 | 示例 |
|----|------|------|
| **玩家 UI** | 中文定稿表（§三 §四） | 按钮：「食用」 |
| **帮助/设计文档** | 与 UI 一致 | 不用「取餐」 |
| **REST 路径** | 英文、稳定 | `/records/orders/{id}/pickup` |
| **四象/schema** | 英文键 | `stack`, `offer`, `message` |
| **commit/PR 说明** | 中文可写「确认收进背包」 | 注明对应 `pickup` |

**不必为了「统一」立刻改 API 路径**；新接口优先用 `receive` / `consume` / `use` / `stack/add` 语义清晰的命名。

## 六、待统一清单（文档与 UI 逐条消）

### 6.1 高优先级（与 v1.0 玩家可见）

| 现状 | 应改为 |
|------|--------|
| 取餐、取餐中 | **确认收进背包** / 收进背包中… |
| 点面取餐后（通知空状态） | 点面 **确认收进背包后** |
| 已取餐 | **已收进背包** |
| 29 §二 仍写「取餐→背包」 | **通知 → 确认收进背包** |
| 壳层「信箱」 | **通知**（29 旧稿） |

### 6.2 中优先级（设计文档）

| 现状 | 应改为 |
|------|--------|
| SKU | **挂单 / offer**（22 已映射，全文扫尾） |
| 灯油、银币 | **点**（30 已定） |
| 库存、inventory | **背包 / stack** |
| 配送、送达、取件 | **删除或标历史**（35 已定） |
| 穿戴 / 装备槽 | v1.0 **不做**；若做 v2 另定「装备」不与「使用工具」混 |
| grant_item、进库 | 文档写 **放入背包** 或 **stack +1** |

### 6.3 低优先级（v1.1+ 再定文案）

| 概念 | 建议预留用语 |
|------|--------------|
| 制作消耗材料 | **用于制作**（不是「使用」） |
| 丢弃 | **丢弃**（若做） |
| 赠送 | **交给** / **赠送**（若做 player 交易） |
| bounty 交付 | **交差** / **确认交差** / **完成委托**（事 record，不是「放入背包」） |
| trace 留痕 | **留下** / **写在这里** |

## 七、与四象的对应

| 玩家操作 | 事 record | 物 thing |
|----------|-----------|----------|
| 打卡 | `visit` | — |
| 点单 | `order` | `offer` |
| 确认收进背包 | `order` settled | `stack` +1 |
| 放入背包（场景） | 可选 `loot` 或并入 `visit` payload | `stack` +1 |
| 食用 / 使用 | 可选 `consume`/`use` 日志 | `stack` -1 |
| 读通知 | `message` read | — |
| 发/接委托 | `bounty` | — |
| 交差 / 确认交差 | `bounty` submitted / settled | — |

## 八、版本节奏

| 版本 | 用语/操作 |
|------|-----------|
| **v1.0** | 定稿 §三 §四；改 UI「取餐」→「确认收进背包」 |
| **v1.1** | spot 掉落 + **放入背包**；通知模板统一 |
