# 国家叙事与世界事件：设计方如何塑造大环境

> 状态：世界层 / 开发者叙事设计  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、一句话

**国家之间的大戏（战争、盟约、灾变）——由我们作为设计方 / 开发者来编、来推环境**；  
玩家 **自愿参与** 其中的订单、信件、地图变化，**不是**人人必备的实时国战。  
像一季连续剧：**我们写舞台和天气，玩家决定要不要上场跑一趟。**

---

## 二、设计立场：环境 vs 仿真

| | 不做（纯玩家仿真） | 做（设计方塑造环境） |
|--|-------------------|----------------------|
| 战争 | 两国玩家实时对打、占城 | **世界季「雾桥冲突」**：官方推进阶段 + 可选贡献单 |
| 外交 | 全靠玩家写信决定存亡 | **开发者设定条约节点** + 玩家大使信影响「舆论条」 |
| 主线 | 强迫全员跟战争进度 | **公告栏挂出**；不参战也能逛地图、点菜 |
| 同步 | 国战必须同时在线 | **阶段切换**按服务器时间；个人异步接单 |

与 `02` 一致：**无个人主线**；世界事件是 **大环境**，不是 **你的作业本**。  
与 `11` 一致：国家日常用信箱；**大战役**由设计方开 **「世界季」**。

---

## 三、设计方管什么、玩家管什么

```
┌─────────────────────────────────────────────────────────┐
│  设计方（L0 / Studio / 官方叙事）                          │
│  · 世界季主题、阶段时间表、地图状态、势力关系基线           │
│  · 官方 Blueprint（战役节点、世界订单模板）                 │
│  · 公告栏 / 使馆电报文案、地点叙事更新                      │
│  · 胜负条件与阶段结局（写进服务器 flag）                    │
└───────────────────────────┬─────────────────────────────┘
                            │ 发布到环境
                            ▼
┌─────────────────────────────────────────────────────────┐
│  环境层（玩家感受到的「天下大势」）                        │
│  · 地图链接变色、封锁、新地点开放                           │
│  · 势力公告栏头条、港务信箱「战报」                         │
│  · 订单池多一批「战时」悬赏（护送、情报、物资）             │
│  · 地点痕迹主题变（前线粉笔、难民留言）                     │
└───────────────────────────┬─────────────────────────────┘
                            │ 自愿参与
                            ▼
┌─────────────────────────────────────────────────────────┐
│  玩家（个人选择）                                          │
│  · 接不接战时单、站不站队、写信不写信                       │
│  · 小团体公会包单、律师审战时举报案                         │
│  · 口味谱记录你常接哪类战争订单 → 你是「后勤党」还是「调查党」  │
└─────────────────────────────────────────────────────────┘
```

**设计方塑造「天气」；玩家决定「要不要出门」。**

## 四、如何把「战争」设计成异步世界季（非 RTS）

### 4.1 战争 = 分阶段的官方叙事 + 可选贡献

不做兵棋；做 **章节**：

| 阶段 | 设计方做什么 | 环境变化 | 玩家可选参与 |
|------|--------------|----------|--------------|
| **序幕** | 发使馆电报、公告栏头条 | 地图出现「紧张」主题色 | 读信、讨论（信箱） |
| **动员** | 开放「战时订单池」 | 新悬赏标签 `wartime` | 接护送、筹物资单 |
| **交锋** | 推进官方 Blueprint 节点 | 某地点暂时封锁/开放 | 完成阶段目标单（全服累计条） |
| **转折** | 发第二封「战报」 | 痕迹区刷新官方叙事粉笔 | 情报单、调查单 |
| **终局** | 写死 `world_flag: bridge_war_end` | 地图恢复、新地点解锁 | 领邮箱「终战」奖励（手动领） |

**胜负**：推荐用 **多轮阵营投票** 计局（见 §4.5）——不是某国玩家 PVP 打出来的。

### 4.2 异步参战方式举例

| 参与 | 像什么 | 系统实现 |
|------|--------|----------|
| 运粮 | 后勤单 | 跑腿单 × 战时标签 |
| 侦查 | 情报单 | 到达地点打卡即贡献 +1 |
| 舆论 | 大使写信 | 使馆信箱；不计硬胜负，只改「民心条」装饰 |
| 公证 | 战时举报 | `09` 案型：走私、谣言粉笔 |
| 旁观 | 读战报 | 零参与；地图仍可走 |

**没有人必须上线开会打仗**；全服进度条可以 **7 天累计**，错时贡献。

### 4.3 同步「军事会议」仅作 spice（可选）

`11` 已说：默认信箱。  
若某一阶段要 **首领同步表决**，设计方 **预约 1 小时会议厅**——**例外**，不是战争常态。

### 4.4 两国开战时，当地玩家能当「士兵」吗？

> 问题：假如设计方让两国进入战争，**身处两国的人**能否选择当兵上战场？

**能「选择参战」，但不是强制征兵，也不是同步战场。**

| 原则 | 说明 |
|------|------|
| **所在地 ≠ 必须站队** | 地图显示「此地属潮灯港」只是 **打卡/主题**；不自动把你登记为士兵 |
| **自愿登记** | 战时开放「志愿兵 / 雇佣兵」入口（点一下即身份皮肤，可撤销） |
| **无主线** | 不参战仍可点菜、逛店、当律师；**没有「国人必上」**（`02`） |
| **不是 RTS** | 「士兵」= 接 **战时标签订单**（前线护送、侦查、守据点打卡），异步完成 |
| **第三方** | 拾遗院中立国玩家可只接 humanitarian 单，或完全不接 |
| **胜负不靠个人 PVP** | 你贡献 +1 进全服条；终局仍由设计方世界季定调 |

**两国玩家各能做什么（举例）：**

```
潮灯港玩家（可选）          边境势力玩家（可选）
    │ 志愿登记「港务营」          │ 志愿登记「边境营」
    ▼                            ▼
接 tag=wartime, side=harbor 单   接 tag=wartime, side=border 单
    │                            │
    └──────────┬─────────────────┘
               ▼
        全服阶段贡献条 +1（异步累计）
               ▼
        设计方终局剧本（非谁在线谁赢）
```

**「士兵」在文本里的样子：**

- 硬：完成了一单 `wartime_escort`，背包少 1 绷带、声望 + 潮灯港战时  
- 软：角色卡可显示「曾登记港务营」；邮箱收战报  
- 不做：两人实时对砍、占格、掉线即阵亡

**若玩家不登记：** 仍是旅人/食客；只是地图主题变、公告栏多看几条电报。

**幽默但受馆规约束：** 厨师仍可吹牛「我上过前线」——L3 叙事；若接战时单则有 L2 订单记录为证（`13`）。

### 4.5 胜负机制：多轮投票定阵营（推荐）

> 比喻：**不是打一仗定输赢，而是连投几次票**——哪个阵营在更多「轮次」里得票，战争就归谁；  
> **给胜方投过票的玩家** 领奖励。

#### 4.5.1 一轮战争 = N 次投票（局）

设计方在世界季里开 **若干轮投票**（建议 **3～7 局**，奇数防平）：

```
世界季「雾桥之冬」
  第 1 局投票（72h）→ 潮灯港 胜
  第 2 局投票（72h）→ 边境营 胜
  第 3 局投票（72h）→ 潮灯港 胜
  第 4 局投票（72h）→ 潮灯港 胜
  ─────────────────────────────
  局分 3 : 1  →  战争总胜负：潮灯港
```

| 概念 | 说明 |
|------|------|
| **一局（一轮投票）** | 开放一个投票窗；玩家异步投 **阵营 A / 阵营 B**（或弃权） |
| **当局胜方** | 该窗内得票多的一方 |
| **战争胜方** | **赢局更多** 的阵营（如 5 局里赢 3 局） |
| **平局** | 局分相同 → 设计方预定规则：加时一局 / 按序幕贡献条 / 叙事定为停战 |

#### 4.5.2 玩家怎么投

| 规则 | 建议 |
|------|------|
| **自愿** | 不投也能玩别的；无强制站队 |
| **每局一票** | 每玩家每局只能投一次（服务器记 `user_id + round_id`） |
| **可换边** | 允许：张三第 1 局投 A、第 2 局投 B——**每局独立** |
| **所在地不绑票** | 在潮灯港地图也可投边境营（雇佣兵叙事） |
| **异步** | 72h 内随时投；不等同时在线 |

投票入口：壳层「战时」挂件 / 势力公告栏顶部 / 系统邮箱里的「战报附投票链接」。

#### 4.5.3 奖励：谁领、领什么

**你的设想（采纳）：**

> 战争结束后，**曾对最终胜方投过票的玩家**（在任意一局里投过即可）→ 系统邮箱发奖 → **手动领取**（`02`）。

| 奖励层级 | 对象 | 示例 |
|----------|------|------|
| **大胜** | 曾对 **战争总胜方** 投过至少一票的玩家 | 灯油、战时徽章、终局 lore 解锁 |
| **小胜（可选）** | 单局投中 **当局胜方** 的玩家 | 每局结束后小红包，鼓励每局来看 |
| **无奖** | 从未投胜方 / 全程弃权 | 无惩罚，只是没礼包 |
| **投败方** | 不罚 | 符合无主线、不羞辱败者 |

```
战争结束 → 胜方 = 潮灯港
    → 查表：谁在 round_1/2/3/4 曾投过 harbor
    → 符合条件的 user_id → 系统邮箱「胜方谢礼」
    → 玩家打开邮箱点「领取」
```

**硬记录（L2）**：`war_votes(user_id, season_id, round_id, side)` —— 领奖凭证，不是台词（`13`）。

#### 4.5.4 与订单、士兵、叙事的关系

| 手段 | 关系 |
|------|------|
| **投票** | 定 **战争总胜负** 的主机制（本节） |
| **战时订单** | 可选：完成一单 = 多算 0 票？**MVP 建议不加权**，避免刷票；或 v2「1 单 = 1 票」与裸投二选一 |
| **志愿兵** | 皮肤/角色卡；**不自动绑投票** |
| **设计方** | 定季、局数、每局文案战报；**不手动指定胜方**（除非紧急叙事止损） |

**比喻总结：**

> 战争像 **系列赛**，每场是一次 **全民（自愿）公投**；  
> 赢更多场次的阵营夺冠；**押对冠军的人分礼包**——不是在前线互砍。

#### 4.5.5 防刷与馆规

| 风险 | 对策 |
|------|------|
| 小号刷票 | 新号冷却、每局每账号一票、关联号检测 |
| 无人投票 | 该局「流局」不计分，或按双方订单贡献代替（待定） |
| 平战争 | 奇数局数；局分平则加时 |
| 泄露胜方提前领奖 | 奖励只在 **全季结束** 后一次性发大胜 |

#### 4.5.6 MVP 最小版

1. 两阵营（潮灯港 vs 边境营）  
2. **3 局投票**，每局 72h  
3. 每局多数胜；**2 局先赢** 者战争胜  
4. 战争结束 → 曾对胜方投过票者 → 邮箱 1 份谢礼（手动领）  
5. 不做战时订单加权、不做实时战场

## 五、设计方工作流：从一季世界事件到上线

### 5.1 六步流水线（建议）

```
① 定季名与母题
   例：「雾桥之冬」——潮灯港 vs 边境封锁，拾遗院中立

② 写阶段表（时间轴）
   第 1 周序幕 → 第 2 周动员 → … → 第 4 周终局
   每阶段：开始时间（服务器）+ 结束条件

③ 绑环境资产
   · 地图：哪些 location 封锁/变色/新开
   · 公告栏：每阶段 1～3 条官方文案
   · 信箱：使馆电报模板
   · 订单池：每阶段注入哪些模板单（Blueprint）

④ 做官方 Blueprint（战役用）
   不是卖给人的 SKU，是 **世界运行时**：
   · 全服贡献条、阶段 flag、终局分支

⑤ 沙盒 + 内部试玩
   测：不接单的人能否正常逛店？接单的人能否异步贡献？

⑥ 发布 / 回滚
   · 公告栏 + 邮箱通知（不弹窗推送，`02`）
   · 阶段 cron 或手动按钮切换（运维）
   · 季终归档：痕迹保留、flag 写入史官页
```

### 5.2 设计方用的工具（与 `07` 同族）

| 工具 | 用途 |
|------|------|
| **世界 Blueprint** | 阶段机、全服计数、终局 flag（玩家不可见 SKU） |
| **世界百科** | 地点、势力、NPC 电报署名 |
| **公告/使馆模板** | 复制季名填空发报 |
| **订单模板注入** | 向池子加 `wartime` 标签单 |
| **地图配置** | `location.blocked_until`、主题 skin |

**开发者不写新服务器逻辑每季**——新季节 = 新 Blueprint + 新文案 + 新配置。

## 六、环境塑造的「感官清单」

玩家怎么 **感到** 天下变了？不必全做，每季选 3～5 项：

| 感官 | 做法 |
|------|------|
| **视觉** | 地图链接色、势力旗、壳层小角标「战时」 |
| **文字** | 公告栏、使馆电报、地点 opening 段落换文案 |
| **经济** | 战时订单报酬略高、某物资 tag 紧缺（系统调价） |
| **社交** | 痕迹区官方粉笔、信箱「战报」 |
| **音频** | （后期）进站轻微氛围音 |
| **规则** | 某类单仅限本势力接；跨境单增加 |

**环境塑造 = 多通道一致说同一件事**：「雾桥那边打起来了。」

## 七、与联盟、国家、玩家的关系

| 层级 | 在大事件中的角色 |
|------|------------------|
| **设计方** | 编季、推阶段、定终局 |
| **联盟（v2）** | 季中可插入「雾桥公约紧急条款」剧情 |
| **国家/势力** | 公告栏不同立场；使馆信口径不同 |
| **公会** | 包战时单、集体贡献 |
| **个人** | 接不接单、口味谱记录立场 |

**国家不是战争引擎的拥有者**——国家是 **叙事皮肤 + 公告出口**；引擎在官方世界 Blueprint。

## 八、MVP：先不要做「国战」，做「一起环境事件」

| MVP 做 | 说明 |
|--------|------|
| **一次「小事件」** | 如「旧栈桥断缆 7 日」——单地点封锁 + 3 类临时订单 |
| **2 条官方公告** | 序幕 + 修复完成 |
| **1 个全服进度条** | 贡献满则解锁地点 |
| **邮箱终局奖励** | 参与过至少一单的可领（手动领） |

| MVP 不做 |
|----------|
| 两国永久胜负、占城、玩家宣战 |
| 多阶段长篇战争季 |
| 同步军事会议 |

**验证**：玩家是否感到「世界动了一下」，而不是「被逼打仗」。

### v2 第一场正式「世界季」

- 4 周、3 势力立场、5 阶段  
- 终局两分支（全服条走 A/B）  
- 战后地图永久留一处「战痕」地点

## 九、设计原则（给设计方自己）

| 原则 | 说明 |
|------|------|
| **大环境，小强迫** | 事件在公告与地图上；不锁非战时玩法 |
| **异步贡献** | 进度条按天累计，不按同时在线 |
| **官方编，玩家演** | 战争结局设计方定；玩家演后勤、情报、律师 |
| **可归档** | 每季结束有史官页 + 痕迹，成为 lore |
| **与点菜共存** | 战时仍可「我要」点非军事口味的单 |
| **失败可接受** | 某季参与低 → 下季缩短、换母题，不加大强迫 |

## 十一、小结

| 问题 | 答案 |
|------|------|
| 大国战争谁来做？ | **设计方**编世界季 + 官方 Blueprint + 环境配置 |
| 玩家做什么？ | **自愿**投票、接战时单、写信——异步 |
| 战争谁赢？ | **多轮投票**：赢局多的阵营胜；投过胜方票的玩家领奖 |
| 怎么塑造环境？ | 地图 + 公告 + 信箱 + 投票挂件 **同主题** |
| MVP？ | **3 局投票** 定胜负 + 胜方投票者邮箱谢礼 |
| 与无主线？ | 世界在变，**你不是必须上场的那条线** |

> 设计方是编年史官兼舞台监督：  
> 雾桥起了战事，港务信箱夜里会多一封电报；  
> 你想运粮就去订单池，想喝茶仍可点菜——  
> 天下大事在此，不必人人皆兵。
