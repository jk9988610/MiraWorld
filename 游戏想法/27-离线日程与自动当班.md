# 离线日程与自动当班：厨师、骑手离线也能干活

> 状态：自动化履约 + 日程  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  
> 原则：**事件驱动，非实时仿真**；**有预算上限**；**在线优先**  

---

## 一、要什么

玩家设定 **离线日程表** 后，角色离线时仍可：

| 角色 | 自动做什么 |
|------|------------|
| **餐厅厨师（雇员）** | 默认开启：备料（不够则按菜单 **自动采购**）→ **按距离/店铺规则接单** → **自动烹饪** |
| **骑手** | 在服务区域内 **自动接配送子单** → 按 ETA 状态机 **自动送达** |
| **店主** | 可选：仅 NPC 级自动（或自己兼厨师 auto） |

**不是** 24 小时挂机刷怪；是 **异步订单流水线** 在玩家不在时由 **系统代理执行**（馆里记在你账上）。

---

## 二、和「异步优先」怎么不打架

| 误解 | 实际 |
|------|------|
| 离线要模拟每秒钟切菜 | **否** — 订单事件触发一步，或定时批处理 |
| 必须 WebSocket | **否** — 上线读信箱摘要即可 |
| 离线比在线更强 | **否** — **在线手动接单优先**；自动队列为辅 |

**口诀：日程开关 + 事件推进 + 日报进信箱；不跑后台 MMORPG 仿真器。**

## 三、核心对象

### 3.1 离线日程 `work_schedule`

```text
work_schedule
  user_id
  enabled              # 总开关
  timezone             # 默认 UTC 或用户选
  windows[]            # 简易：周几 + start + end（本地时间）
  roles[]              # chef | rider | clerk
```

**MVP 极简版：** 不做复杂周历，只有：

- `auto_work_on: true/false`
- `daily_window: "09:00-23:00"`（一行字符串）

### 3.2 自动当班配置 `auto_work_profile`

按 **角色 + 绑定雇主** 一份：

```text
auto_work_profile
  user_id
  role: chef | rider
  shop_id NULL         # 厨师绑店；骑手可 NULL=公共池
  enabled              # 厨师雇员：默认 true（用户可关）
  rules_json           # 见下表
```

| 规则键 | 厨师默认 | 骑手默认 | 说明 |
|--------|----------|----------|------|
| `auto_accept` | true | true | 自动接单 |
| `auto_buy_ingredients` | true | — | 缺料时自动买 |
| `buy_budget_daily` | 50 灯油 | — | 日采购上限 |
| `buy_source` | `shop_wallet` → `system_catalog` | — | 先扣店司库，不足再扣个人授权额度 |
| `max_concurrent` | 2 | 1 | 同时几单 |
| `service_regions[]` | 继承店铺 | 自选 region | 与 `24` 一致 |
| `max_delivery_hops` | — | 3 | 超过不自动接 |
| `pause_if_wallet_low` | true | true | 余额/预算不足则停 |

### 3.3 代理执行记录 `auto_work_log`

离线期间每笔自动动作写日志，上线合并成 **《当班日报》** 进系统信箱。

### 3.4 玩家如何设置日程表（MVP 界面）

#### 入口在哪

| 入口 | 谁能用 |
|------|--------|
| **我的 → 当班设置** | 所有人（设个人总日程） |
| **店铺管理 → 我的当班** | 该店雇员厨师（店规 + 个人规则） |
| **骑手执照页 → 自动配送** | 注册骑手 |
| **录用成功信** | 带链接「去设置当班」— 默认已开，可改 |

壳层「我的」旁可显示小标：**当班中** / **已排班离线**（仅 `enabled && 在窗内`）。

#### 设置页长什么样（MVP 一屏搞定）

```
┌─────────────────────────────────────────┐
│  当班设置                                │
├─────────────────────────────────────────┤
│  [开关] 离线时自动当班                    │
│                                         │
│  每日时段   [ 09:00 ] — [ 23:00 ]        │
│  （时区：Asia/Shanghai · 可改）          │
│                                         │
│  ── 当前身份：少盐食堂 · 厨师 ──          │
│  [开关] 本店自动接单烹饪    （默认开）    │
│  [开关] 缺料时自动采购      （默认开）    │
│  日采购上限  [ 50 ] 灯油（扣店司库）      │
│  同时最多    [ 2 ] 单                   │
│                                         │
│  ── 骑手（若有执照）──                   │
│  [开关] 自动接配送单                      │
│  常跑区域    [√港区] [√栈桥线] [ 镜湖 ]   │
│  最远       [ 3 ] 跳                    │
│                                         │
│  [ 保存 ]                                │
│                                         │
│  预览：今日 09:00–23:00 内离线将自动当班   │
└─────────────────────────────────────────┘
```

**MVP 不做：** 拖拽周历、多段时段、按店铺不同日历。  
**v2 再加：** 周几勾选、多段 `09-12` + `17-22`、节假日关闭。

#### 设置步骤（玩家视角）

```
1. 打开「我的」→「当班设置」
2. 打开总开关「离线时自动当班」
3. 填每日时段（默认 09:00–23:00，可改）
4. 若已是某店厨师 → 确认「本店自动接单」为开（录用时默认已开）
5. 按需调：自动买料、日预算、同时几单
6. 若是骑手 → 勾选常跑区域、最远跳数
7. 点保存 → 立即生效（在时段内下线即按规则跑）
```

#### 录用时默认（不用玩家先设也能跑）

| 事件 | 系统默认 |
|------|----------|
| 被店录用为厨师 | `auto_work_profile.enabled=true`，继承店 `region` |
| `work_schedule` 不存在 | 创建：`enabled=true`，`09:00-23:00`，时区跟浏览器 |
| 玩家从未打开设置页 | **照样自动当班** — 设置页是改默认，不是前置条件 |

信箱发一封：**「你已成为少盐食堂厨师，离线默认自动当班（09–23）。点此调整。」**

#### 保存时服务器写什么

```json
// PUT /miraworld/api/me/work-schedule
{
  "enabled": true,
  "timezone": "Asia/Shanghai",
  "daily_window": { "start": "09:00", "end": "23:00" }
}

// PUT /miraworld/api/me/auto-work/chef?shop_id=...
{
  "enabled": true,
  "auto_accept": true,
  "auto_buy_ingredients": true,
  "buy_budget_daily": 50,
  "max_concurrent": 2
}
```

#### 怎么判断「现在在日程内」

```text
in_window(now, user.timezone):
  local_time = convert(now, timezone)
  return start <= local_time <= end
```

跨日时段（如 22:00–02:00）**MVP 不支持**；v2 再议。

#### 店主能否改雇员的日程？

| 权限 | MVP |
|------|-----|
| 店主强制关某厨师 auto | **可以**（店规优先） |
| 店主替雇员改时段 | **否** — 时段归个人；店只能开/关「本店 auto」 |
| 店主设店级营业窗 | **可以** — 店打烊则全体 auto 暂停 |

#### 常见问题（帮助页文案）

| 问 | 答 |
|----|-----|
| 不在时段内会接单吗？ | **不会** |
| 在线时还 auto 吗？ | **在线手动优先**；auto 主要服务离线 |
| 关总开关后雇员身份呢？ | 仍在店，只是离线不自动做单 |
| 改时区何时生效？ | 保存后立即按新时区算窗 |

## 四、执行模型（易实现：事件驱动）

**不要** 每 5 秒 tick 全服厨师；用 **订单状态变更时** 尝试匹配自动当班者。

```
订单 paid_escrow
    │
    ▼
dispatch_service.try_assign_cook(order)
    │
    ├─ ① 在线且手动接单的厨师（店内队列）— 优先
    │
    ├─ ② 离线 auto 厨师（schedule 在窗内 + enabled）
    │       → assign chef_id
    │       → ensure_ingredients()  # 可能触发 auto_buy
    │       → cook()  # 状态机一步
    │
    └─ ③ 无人 → 等待 / 馆驿卒托底（`17`）
```

配送同理：

```
order ready_for_delivery
    │
    ▼
dispatch_service.try_assign_rider(order)
    ├─ 在线骑手抢单池
    └─ 离线 auto 骑手（region + hops 匹配）
            → 写 milestones + 按 hops 算 delay 后 mark_delivered
```

### 4.1 「多久送达」离线时怎么算

不模拟走路，用 **`24` 的 hops 公式** 设 **scheduled_at**：

```text
deliver_at = now + cook_remain + base + hops * per_hop
```

到点由 **cron 每分钟** 扫 `orders WHERE status=delivering AND deliver_at <= now` → 置 `delivered` → 通知顾客。

**一个定时任务足够**，不必每人一个 timer。

## 五、厨师自动流水线（细）

### 5.1 默认：餐厅雇员厨师 **自动工作开启**

录用时（`21`）写入：

```text
auto_work_profile.enabled = true   # 默认开，可关
```

玩家关掉的含义：「我离线只领工资不干自动单」—— 若店规要求当班则只接 **手动单**。

### 5.2 自动备料 / 采购

```
cook(order):
  recipe = sku.recipe_id
  for each input in recipe.inputs:
    if shop_stock[input] < need:
      if auto_buy_ingredients and under daily_budget:
        purchase(input, qty, from=buy_source)
      else:
        order.waiting_stock → 信箱通知店主/厨师
        return
  deduct stock → output item → order.ready
```

| 采购来源 | 说明 |
|----------|------|
| `shop_wallet` | 店司库扣灯油（`23` MVP 可合并店主钱包） |
| `system_catalog` | 系统标价 T0 材料（`16` 铸造价） |
| `chef_delegate` | 厨师授权的个人日额度（防店司库被雇工刷空） |

**日预算耗尽** → 停自动接单 + 信箱：「今日采购额度已尽。」

### 5.3 自动接单（距离 / 区域）

与 `24` 共用：

```text
eligible if:
  order.shop.region in chef.service_regions
  OR order.delivery_hops <= chef.max_hops
  AND chef.concurrent < max_concurrent
  AND work_schedule.in_window(now)
```

**店内单**（堂食）：hops=0，优先自动做。  
**外卖单**：看店铺是否开启 `auto_delivery_cook`（后厨做完即等骑手）。

## 六、骑手自动配送

```
auto_rider.enabled and in_window
  → 订阅 region 内 ready 配送子单
  → 按 hops 升序接 1 单（近的优先）
  → status delivering, deliver_at = f(hops)
  → cron 到点 → delivered → 分配送费进骑手 wallet
```

**不与在线骑手抢单？**  
规则：**在线可见单 30s 后** 才流入 auto 池（给真人优先窗口）。

## 七、玩家上线看见什么

系统信箱 **《当班日报》**（手动点领汇总，钱已入账）：

```text
你离线期间（9:00–23:00）：
  · 烹饪完成 5 单 · 分得 15 灯油
  · 自动采购 雾港面粉×10 · 花费 8 灯油（店司库）
  · 配送完成 2 单 · 分得 6 灯油
  · 1 单因缺料等待（少盐食堂）
[ 查看明细 ] → auto_work_log
```

`22` 面板状态离线时显示：**「自动当班中（厨师）」** — 仅当 `enabled && in_window`。

## 八、实现落点（对齐 `26`）

| 模块 | 新增 |
|------|------|
| **profile** | `work_schedule` CRUD |
| **jobs** | 录用时创建默认 `auto_work_profile` |
| **orders** | `dispatch_service.py`：try_assign_cook / rider |
| **shops** | `shop_stock` 或复用 inventory 绑 shop_id |
| **wallet** | 采购扣款、分账不变 |
| **catalog** | `POST /internal/purchase-material` 标价购 |
| **mail** | 日报聚合 job（用户上线或每日 0 点） |
| **worker** | 单进程 cron：`process_due_deliveries()` 每分钟 |

**新表（MVP）：**

```text
work_schedules        (user_id, enabled, window_json)
auto_work_profiles    (user_id, role, shop_id, rules_json)
auto_work_logs        (id, user_id, order_id, action, at, meta_json)
shop_inventory        (shop_id, item_id, qty)   # 或 shop_id 绑 owner 背包子集
```

## 九、防滥用

| 风险 | 馆规 |
|------|------|
| 离线 24h 无限刷 | `max_concurrent` + 日采购预算 + 信誉门槛 |
| 自动买空店库 | `buy_budget_daily` + 店主可关 `auto_buy` |
| 与在线抢光单 | 在线优先 30s + 同店雇员上限 |
| 同号店主+雇工闭环 | 沿用 `01` 同人禁闭环 |
| 零成本自动烹饪 | 采购必须扣灯油；系统价 ≥ 铸造底价 |

## 十二、小结

| 问题 | 答案 |
|------|------|
| 日程怎么设？ | **我的→当班设置**：总开关 + 每日时段 + 分角色规则；录用默认已开 |
| 离线日程？ | **简易时间窗 + 总开关**；v2 再做周历 |
| 厨师离线？ | **默认 auto**；够料则烹，不够则 **按预算自动买** |
| 接单？ | **事件驱动**；区域/跳数过滤；**在线优先** |
| 骑手？ | **region + hops** 自动接；**定时任务**到点送达 |
| 怎么实现？ | **dispatch_service + cron**，不建离线仿真世界 |
| 玩家怎么知？ | **当班日报**进信箱 + `auto_work_log` |

> 人不在馆里，日程替你点灯、备料、出锅；  
> 钱和料都记在账上，上限和窗口感得住——  
> 不是第二个你在跑，是馆规替你按单推进。
