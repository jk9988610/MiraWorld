# 系统托底订单：很久没人接，馆里怎么办？

> ⚠️ **v1.0 不做** — 无馆驿卒、无超时托底、无配送代送。本文供 v2+ 参考。  
> 状态：订单超时与系统代履约  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  

---

## 一、一句话

订单挂太久没人接，**系统可以替玩家「把事办完」**——但只能办 **机器能客观验收** 的事；  
**非得人来做** 的单（叙事、判断、创作、人情），只能 **加价、回池、退款**，不能假装玩家做过。

---

## 二、判断标准（一张表记住）

| 问题 | 系统能托底 | 必须玩家接单 |
|------|------------|--------------|
| 验收靠 **计数/地点/物品 ID**？ | ✅ | — |
| 验收靠 **文笔/创意/扮演**？ | — | ✅ |
| 交付物是 **系统铸造数字物**？ | ✅ | — |
| 需要 **真人厨师/编剧** 署名？ | — | ✅ |
| 发单方在「我要」里勾了 **「要玩家厨师」**？ | — | ✅ |
| 标了 **叙事/沉浸** 不可外包？ | — | ✅ |
| 报酬来自 **托管**，系统能代扣代发？ | ✅ 前提 | ✅ 前提 |

**口诀：能写成 `if 背包有 X and 到了 Y then done` 的，系统能托底；其余等人。**

## 三、系统**可以**托底的订单类型

### 3.1 列表

| 类型 | 例子 | 系统怎么做 | 与现有文档 |
|------|------|------------|------------|
| **跑腿 / 信使** | 把灯油从 A 送到 B | 虚拟「馆驿卒」走状态机：取件→送达→验收 | `01` 系统派单 |
| **收集 / 交付物品** | 收集 3 个 `item_fog_salt` | 若发单方背包已有或系统铸造补齐（规则内） | `01` 客观验收 |
| **标准厨具 / 材料铸造** | 订制汤勺无人接 | `16` 系统铸造 + 扣托管款作「馆费」 | `16` |
| **数字商品发货** | 买 SKU 调查包 | 始终系统 `grant_item` | `01` §十五 |
| **简单打卡 / 到访** | 到某地确认一脚印 | 系统代打卡（仅当订单允许代行且非沉浸单） | `03` |
| **超时清算** | 悬赏无人接 N 小时 | **不是完成**，是：加价回池 / 部分退款 / 拆单 | `01` §4.7 |
| **战时基础物资** | 运粮贡献 +1 | 低优先级系统单，贵且平淡 | `12` |
| **退款 / 解冻** | 商家申诉期过 | 纯状态机 | `09` |

### 3.2 托底时的体验（建议）

与 `02` 一致：**系统代做 = 贵、平淡、不抢主成长**（或只给极少「后勤声望」）。

| 项 | 建议 |
|----|------|
| **触发** | 无人接单超过 **N 小时**（按订单类型配置） |
| **通知** | 系统邮箱：「馆驿卒接走了你的单」——不弹窗 |
| **费用** | 从托管报酬扣 **馆驿费**（高于玩家接单市价） |
| **叙事** | L3：「一个不爱说话的馆丁办完了」；L2：订单状态 `done_by: system` |
| **成长** | 食客侧：**口味经验减半或为零**；发单方任务可完成，但不享受「玩家厨师加成」 |

```
玩家悬赏挂 48h 无人接
    → 发单方邮箱：「是否请馆驿代送？（多扣 20% 灯油）」
    → 同意 / 默认策略（设置里可选总是/从不）
    → 系统履约 → 结算
```

**可选：** 不自动托底，先问发单方（异步信箱确认链接）。

## 四、系统**不能**托底、必须玩家接单的类型

| 类型 | 为什么必须人 | 无人接时怎么办 |
|------|--------------|----------------|
| **定制叙事 / 调查剧本** | 验收要创意与对话质量 | 加价、延期、退款、改标「降低口味」 |
| **服务单（调查/陪护/谈判）** | 软交互 + 主观完成度 | 回池、推荐降价、取消退款 |
| **玩家明确要「玩家厨师」** | `02` 点菜自选 | **永不系统代做** |
| **Blueprint / 方案订制** | B₁ 创作，非状态机 | 延长征集、转方案市场 |
| **代工带工艺品质** | 随机品质 roll 需工匠身份 | `16` 仅标准件可铸造，非工艺装 |
| **陪玩 / 教学 / 角色扮演** | 本质是人 | 只能等人 |
| **律师评议 / 举报申诉** | 馆规裁断 | 系统只做②初判，⑤必等人（`09`） |
| **情报「口述」类** | 软信息不进硬系统 | 禁止托底 |
| **高报酬套利单** | 系统托底会被刷 | 不设托底，只超时失败 |
| **沉浸叙事单（不可外包）** | 设计方标记 | 仅回池或退款 |

**口诀：要「一个人味」的单，馆丁替不了。**

## 五、按订单字段自动判定（实现提示）

每个订单发布时带 `fallback_policy`：

| 值 | 含义 |
|----|------|
| `none` | 永不系统托底（默认：叙事/服务/玩家厨师） |
| `ask` | 超时后问发单方 |
| `system_runner` | 可馆驿卒跑腿 |
| `system_mint` | 可系统铸造标准物（`16`） |
| `refund_only` | 超时只退款 |

**自动规则（发布时默认）：**

```text
if tags contains player_chef_required → none
if tags contains narrative_immersive → none
if验收器 == ObjectiveItemDelivery → system_runner 或 ask
if type == digital_sku → always system（即时，无托底概念）
if type == custom_craft AND item_tag in kitchen_utensil_std → system_mint
```

## 六、三种「没人接」结局（别混为一谈）

| 结局 | 适用 | 说明 |
|------|------|------|
| **A. 系统托底完成** | 客观单 + 政策允许 | 事办完，贵，成长打折 |
| **B. 回池加价** | 想等人 | 报酬 +X%，再挂 |
| **C. 失败退款** | 叙事单 / 发单方选取消 | 托管退回减手续费 |

**不是**所有挂单最终都该被系统做完——否则玩家厨师没饭吃。

## 七、与厨房 / 词条例子的衔接（`16`）

| 情况 | 托底？ |
|------|--------|
| 「做一把标准汤勺」无人接 | ✅ `system_mint`，扣托管 |
| 「做一把 **刻名** 汤勺送给 NPC」 | ❌ 要工匠 |
| 「熬汤」订单只要 `has ladle` | ✅ 若系统已铸造勺子可完成熬汤节点 |
| 「熬汤」同时要厨师写 **原创贺词** | ❌ 等人 |

## 八、防刷与馆规

| 风险 | 对策 |
|------|------|
| 故意挂单等系统贵托底 | 托底费 > 市价；叙事单 none |
| 自卖自买刷系统完成 | 同号闭环禁止（`01`） |
| 系统完成给高额成长 | 成长减半/为零 |
| 发单方永远点「总是托底」 | 日上限；高价累进 |

---

## 九、MVP 建议

| 做 | 不做 |
|----|------|
| 跑腿类超时 → **ask** 是否馆驿代送 | 叙事单自动完成 |
| `fallback_policy` 字段 + 3 种结局 A/B/C | 全类型托底 |
| 系统完成标记 `done_by: system` | 假装是玩家做的 |
| 厨具标准件 `system_mint`（`16`） | 工艺装铸造 |

## 十一、小结

| 问题 | 答案 |
|------|------|
| 系统能托底哪些？ | **客观验收**：跑腿、收集、标准铸造、数字发货、允许代行的打卡 |
| 哪些必须玩家？ | **叙事、服务、指定玩家厨师、创作、陪玩、律师、工艺品质、沉浸单** |
| 很久没人接？ | 托底 / 加价回池 / 退款 —— **按类型选，不一刀切** |
| 托底的味道？ | 贵、平淡、成长打折；L2 记 `done_by: system` |

> 馆驿卒能替你跑腿、替你铸一把标准勺；  
> 不能替你写调查、替你陪夜、替你在栈桥上留一句真心话。
