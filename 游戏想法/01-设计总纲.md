## 一、一句话

**化繁为简：核心只有生产与消费。**  
城市自己转；玩家是 **经营者**（带 handle），用资产在闭环里赚钱。  
不绕弯：无配送、无故事输出、无律师判决、无招贤应聘。

---

## 二、四象（口诀：人是谁，地在哪市，事是账，物在谁手）

```
                    ┌─────────┐
                    │ credits │  ← 横切：只有一种钱（点）
                    └────┬────┘
         ┌──────────┼──────────┐
         ▼          ▼          ▼
      【人】      【地】      【物】
     Actor      Place      Thing
         │          │          │
         └────┬─────┴─────┬────┘
              ▼           ▼
            【事】 Record
```

| 象 | 键 | 一句话 | 玩家看见 |
|----|-----|--------|----------|
| **人** | `actor` | 谁在做/谁拥有 | 陈师傅、@handle、系统 |
| **地** | `place` | 在哪座市 | 潮灯市 |
| **事** | `record` | 发生过什么 | 订单、通知、打卡、流水 |
| **物** | `thing` | 什么东西 | 标准汤面、一碗面 |

**Actor 三类：** `player`（handle）· `npc` · `system`。全 API 用 **ActorRef**，禁止多套指人方式。

**地：** 地址只有 **市**；精确定位 = **市 + 人**（NPC 或 handle）。逛点（晚霞岸等）仅文案/彩蛋，不进地址表。

**物：** `item`（定义）+ `stack`（持有）。可买 = **offer**（取代 SKU 一词）。

**事：** `order` · `message` · `visit` · `ledger` · `bounty`（购/售委托）等，统一 record 模型。

**新功能必须先落进四象，否则不排期。**

---

## 三、商品怎么到玩家手里

```
买家点 offer → 扣点 → 卖家履约 → 通知 → 物进背包
```

**没有：** 骑手、配送、取餐 drama。玩家 **确认收进背包**；订单与委托 **一律通知**。

## 四、乌托邦双账本

| 账本 | 说明 |
|------|------|
| **内生** | 机构 ↔ 市民组：工资、消费、卖货（**必须自洽**） |
| **外生 · 城市福利** | 无岗市民 **最低生活补贴**（城市福利基金 + 乌托邦 grant） |
| **外生 · 玩家日投** | 资本家日投资金（规划 v2.1；**不计入**市民平衡） |

**纪律：** 市民钱不能从消费池凭空刷。**在岗** 靠机构工资（≥ 最低工资）；**无岗** 靠温饱补贴。细则见 [04](./04-乌托邦经济.md)。

## 五、Actor 极简（经济层）

| Actor | 职责 |
|-------|------|
| **玩家** | 生产决策（店/offer/NPC 岗）；仅 handle，无市民标签 |
| **机构** | 生产、雇组、发薪 |
| **市民组** | 1000 人/组；消费 |

## 六、其它简化

| 领域 | 做法 |
|------|------|
| 通讯 | 系统 **通知**（经营结果） |
| 地址 | 市 + handle |
| 钱 | **点** / credits |
| 托底 | **最低生活补贴**；**不做** 馆驿卒派单 |

## 七、明确不做（永久）

骑手、配送、招贤、应聘、雇玩家、律师、作家、trace 留痕、中介、委托做某事、叙事产出、Victoria 级 Pop 政治。
