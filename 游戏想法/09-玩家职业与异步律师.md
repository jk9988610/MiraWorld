# 玩家职业与异步律师：馆规下的角色扮演

> 状态：社会规则 + 职业玩法构思  
> 记录时间：2026-09-12  
> 来源：与作者的讨论  
> 定位：许多**职业由玩家扮演**；游戏**不是严肃现实模拟**，但要有**可遵守的规则与氛围**。律师是首个详化的异步职业范例。

---

## 一、一句话

世界里的律师、厨师、信使……可以是**玩家**扮演的；  
律师须先通过一场**很简单的资格考**（愿意参加基本能过），再在**异步合议台**上审阅案件——  
**系统先初判，律师后投票，多数决后结案**；没有同步法庭，没有所有人同时在线。

---

## 二、整体立场：像角色扮演，不是严肃仿真

| 维度 | 本作 |
|------|------|
| 现实法庭 | **不做**同步开庭、举证质证马拉松 |
| 规则与氛围 | **要做**——有馆规、有资质、有裁断记录 |
| 职业感 | 玩家「扮演」身份，系统给**硬边界**（能干什么不能干什么） |
| 与异步世界观 | 一致（`04` 信箱、`03` 痕迹、`05` 按需刷新） |

> 像剧团里的法官：戏服是真的，台词可简，但**不能坏了馆里的规矩**。

---

## 三、玩家可扮演的职业（谱系）

许多职能已在其他文档出现，此处归纳为**职业身份**：

| 职业 | 生活类比 | 主要文档 | 同步度 |
|------|----------|----------|--------|
| **食客** | 下馆子的人 | `02` | 异步 |
| **厨师 / 服务员** | 接单出活 | `02` `01` | 异步 |
| **行者 / 信使** | 跑腿外卖 | `01` | 异步 |
| **店主 / 原料商** | 进销存 | `01` `06` | 异步 |
| **方案方 / 产品方** | 研发与包装 | `07` `01` | 异步 |
| **律师** | 馆规裁断与合议 | 本文、`08` | **异步** |
| **（后期）审计、仲裁员、馆吏** | 查账、复核 | 待定 | 异步 |

**默认原则**：职业玩法 **错时友好**；不要求「全体律师同时上线」。

## 四、律师：资质与入门

### 4.1 为什么要有资质

律师能影响**他人账号、资金冻结、下架**等后果，门槛过低会毁环境（`08`）。  
但门槛过高又没人玩——故：

| 设计 | 说明 |
|------|------|
| **资格考** | 短卷，题量适中（概念上可称「馆规考」）；**偏常识与馆规阅读** |
| **难度** | **故意简单**——认真读帮助页与馆规，愿意参加**基本能过** |
| **目的** | 筛掉完全不看规则的人，而非筛天才 |
| **重考** | 未过可再考；冷却例如 24h（防刷） |
| **通过后** | 获得身份 **`注册律师`**，证书进角色卡 / 邮箱 |

### 4.2 资质边界（能做什么）

| 在资质内 | 不在资质内 |
|----------|------------|
| 在**合议台**对案件投「认同 / 不认同」票 | 私下代他人操作账号 |
| 撰写**评议摘要**（异步留言，供卷宗留存） | 保证胜诉、收现实货币 |
| 按馆规引用条款编号 | 改系统硬数据、绕过托管 |

违规 → 吊销律师资格 + 信誉罚（`08` 先行下架权仍归平台）。

### 4.3 考试内容（示例方向）

- 馆规五条：托管、分账、举报、退款、先行下架  
- 什么证据系统认、什么不认  
- 律师投票是「是否认同系统初判」而非重新侦查  
- 一题：**律师合议是异步的，不需要同时在线**

## 五、异步律师合议：流程（核心）

### 5.1 设计意图

- **不急于即时评判**——争端正热时先冻结，避免骂战升级  
- **系统先给专业底稿**——规则引擎按日志初判  
- **律师群体后置复核**——多数决赋予**正当性氛围**，非替代系统算力  
- **全程异步**——像信箱往来，错时投票

### 5.2 一案的生命周期

```
① 事件发生
   例：举报抄袭 SKU、订单申诉、资金冻结争议、下架不服

② 系统收案 → 自动汇总证据
   order_events、blueprint_hash、举报记录、双方信串摘要…

③ 系统初判（硬）
   输出：初判结论（通过/不通过/部分成立）+ 建议处置 + 馆规条款引用
   → 此时**不立即执行终局**（或仅执行低风险临时措施：如继续冻结）

④ 进入「律师合议台」（异步）
   - 案件公开（脱敏：隐藏现实身份信息，保留 ID 与日志）
   - 符合资质的律师可随时阅览卷宗
   - 律师投：**认同初判** / **不认同初判**（二选一为主，MVP 不做复杂量刑）
   - 可选：写短评议（限字数，进卷宗）

⑤ 投票期结束（例如 72h，或达到最低票数提前结案）
   - 规则：**多数律师认同** → 按系统初判执行终局
   - **多数不认同** → 退回人工复核队列（运营 + 合作律师 L2），或触发二次系统重判

⑥ 结案
   - 结果写入卷宗 → 双方系统邮箱通知（`04`）
   - 执行：解冻/退款/下架维持/恢复上架…
   - 律师参与者得少量声望（防刷：单账号单案只计一次票）
```

### 5.3 与「现实法庭」的差异（刻意简化）

| 现实法庭 | 本作律师合议 |
|----------|--------------|
| 同步开庭 | **72h 投票窗**，随时投 |
| 律师辩论 | **可选短评议**，无实时对线 |
| 法官一人定案 | **系统初判 + 律师多数决** |
| 证据规则极严 | **系统日志为准**（`01` 硬交互） |
| 严肃仿真 | **馆规剧场**——有仪式感，不折磨人 |

### 5.4 系统初判 vs 律师投票：谁说了算？

| 层级 | 权力 |
|------|------|
| **系统初判** | 基于规则的**默认结论**；不可被律师「改判为任意结果」 |
| **律师多数认同** | **确认**初判可执行 → 终局生效 |
| **律师多数不认同** | **不直接改判** → 升级复核（防律师串通改钞） |
| **平台** | 保留对违法、重大风险的**一票否决**（`08`） |

律师是 **合议陪审团氛围**，不是 **第二个服务器**。

### 5.5 防滥投与环境保护

| 风险 | 对策 |
|------|------|
| 律师刷票换币 | 单案一票；奖励声望非货币为主；日投票上限 |
| 律师串通 | 随机抽案参与（后期）；异常一致票型审计 |
| 无人投票 | 期满按系统初判**自动结案**（律师是增强正当性，非阻塞） |
| 拖延正义 | 投票窗有上限；临时措施（冻结）已有 |
| 律师当武器骚扰 | 恶意不认同率高的吊销资质 |

## 六、与合规文档（08）的关系

| `08` 概念 | 玩家律师扮演 |
|-----------|--------------|
| L1 馆规自动化 | **系统初判** |
| L2 合作律师 | **复核队列**（律师多数不认同时） |
| L3 外部司法 | 平台外仍可走现实法律；游戏内合议不替代 |
| 先行下架 | 举报后仍可先冻，合议确认后维持或恢复 |
| 版权侵权 | 卷宗含 hash 比对结果，律师投认同与否 |

玩家律师 **不替代** 平台法务与真实律师；是 **馆内正当性 + 参与感**。

## 七、其他职业是否也要「简单考」？

| 职业 | 建议 |
|------|------|
| 律师 | **要**——影响他人权益 |
| 行者 / 服务员 | **轻量执照**（已有方向 `01`） |
| 商家 | **开店考**——托管与库存常识，同样偏简单 |
| 方案方 B₁ | **模板工作坊通关**（`07` 沙盒即考） |
| 食客 | 无考 |

统一原则：**考的是「读规则意愿」**，不是为难人。

## 八、MVP 可验证什么

1. 馆规考 10～20 题，通过后得「注册律师」  
2. 一种案件类型：**下架申诉**或**订单申诉**  
3. 系统初判 + 72h 投票窗 + 多数认同则执行  
4. 无人投票期满 → 按初判自动结案  
5. 双方邮箱收结案通知；卷宗可查阅（脱敏）  
6. 问玩家：是否感觉「有规矩」又不像上班？

## 十、小结

| 问题 | 答案 |
|------|------|
| 职业谁扮演？ | **玩家**；系统给资质与硬边界 |
| 严肃现实吗？ | **不**；但有馆规氛围与卷宗仪式感 |
| 律师怎么当？ | **简单资格考** → 注册律师 |
| 怎么审案？ | **异步**；系统先初判 → 律师投票认同与否 → 多数决 → 结案 |
| 同步法庭？ | **不做** |
| 律师能改判任意结果吗？ | **不能**；只能确认或触发复核 |

> 案卷放上合议台，像把信投进邮局：律师们睡醒、路过、投下一票。  
> 系统早已写好初稿；众人认同，馆规便落地。
